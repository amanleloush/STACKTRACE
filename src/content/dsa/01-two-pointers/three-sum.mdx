## Problem
Given an integer array, return all **unique** triplets `(a, b, c)` with `a + b + c == 0`. No duplicate triplets in the output.

## Interview-ready explanation

I sort the array and reduce 3Sum to repeated Two Sum with two pointers. For each index i, I treat arr[i] as the smallest element of the triplet and run converging pointers l and r on the suffix after i, looking for arr[l] + arr[r] equal to -arr[i]: move l right if the sum is too small, r left if it is too large. Sorting also makes deduplication cheap: I skip an i equal to the previous one, and after a match I move l and r past equal values. I can stop early once arr[i] is positive. Each i costs O(n), so the total is O(n²) time, which dominates the O(n log n) sort, and O(1) extra space apart from the output and the sort.

**One-liner:** Sort, fix each element as the smallest of the triplet, two-pointer the rest for the negated value, and skip equal neighbours to avoid duplicates; O(n²) time.

## Intuition
Sort the array, then reduce 3Sum to 2Sum. Fix `i` as the smallest element of the triplet; then on the suffix `[i+1, n-1]`, run a two-pointer search for `target = -arr[i]`. The sort enables both the two-pointer step and *cheap* deduplication (just skip equal neighbours). Once you fix `i`, a single O(n) sweep finds every valid `(l, r)`, so the whole algorithm is O(n²) — the O(n log n) sort is dominated.

## Algorithm
1. Sort `arr`.
2. For `i` from 0 to `n - 3`:
   - If `arr[i] > 0`, break — the array is sorted, so every remaining value is positive and no triplet can sum to 0.
   - If `i > 0` and `arr[i] == arr[i - 1]`, **skip** (duplicate triplet root).
   - Set `l = i + 1`, `r = n - 1`, `target = -arr[i]`.
   - While `l < r`:
     - `s = arr[l] + arr[r]`.
     - If `s == target`: record `(arr[i], arr[l], arr[r])`; advance `l` past duplicates and retreat `r` past duplicates.
     - Else if `s < target`: `l++`. Else `r--`.

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> out;
        int n = (int)nums.size();
        for (int i = 0; i < n - 2; ++i) {
            if (nums[i] > 0) break;
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            int l = i + 1, r = n - 1, target = -nums[i];
            while (l < r) {
                int s = nums[l] + nums[r];
                if (s == target) {
                    out.push_back({nums[i], nums[l], nums[r]});
                    while (l < r && nums[l] == nums[l + 1]) ++l;
                    while (l < r && nums[r] == nums[r - 1]) --r;
                    ++l;
                    --r;
                } else if (s < target) {
                    ++l;
                } else {
                    --r;
                }
            }
        }
        return out;
    }
};
```

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> out = new ArrayList<>();
        int n = nums.length;
        for (int i = 0; i < n - 2; i++) {
            if (nums[i] > 0) break;
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            int l = i + 1, r = n - 1, target = -nums[i];
            while (l < r) {
                int s = nums[l] + nums[r];
                if (s == target) {
                    out.add(Arrays.asList(nums[i], nums[l], nums[r]));
                    while (l < r && nums[l] == nums[l + 1]) l++;
                    while (l < r && nums[r] == nums[r - 1]) r--;
                    l++;
                    r--;
                } else if (s < target) {
                    l++;
                } else {
                    r--;
                }
            }
        }
        return out;
    }
}
```

```python
def three_sum(arr):
    arr.sort()
    out = []
    n = len(arr)
    for i in range(n - 2):
        if arr[i] > 0:
            break
        if i > 0 and arr[i] == arr[i - 1]:
            continue
        l, r, target = i + 1, n - 1, -arr[i]
        while l < r:
            s = arr[l] + arr[r]
            if s == target:
                out.append([arr[i], arr[l], arr[r]])
                while l < r and arr[l] == arr[l + 1]:
                    l += 1
                while l < r and arr[r] == arr[r - 1]:
                    r -= 1
                l += 1
                r -= 1
            elif s < target:
                l += 1
            else:
                r -= 1
    return out
```

## Walkthrough
On sorted `arr = [-4, -1, -1, 0, 1, 2]`:

1. **Anchor `i=0` (`-4`), target = 4.** Two-pointer sweep `l=1, r=5` walks every sum `≤ 3 < 4`, so `l` keeps advancing and no triple is recorded.
2. **Anchor `i=1` (`-1`), target = 1.** `l=2, r=5`: `-1 + 2 = 1` — record `(-1, -1, 2)`. Advance to `l=3, r=4`: `0 + 1 = 1` — record `(-1, 0, 1)`.
3. **Anchor `i=2` (`-1`).** `arr[2] == arr[1]` → skip the duplicate anchor.
4. **Anchor `i=3` (`0`), target = 0.** `l=4, r=5`: `1 + 2 = 3 > 0` → `r--`, pointers cross, no new triple.
5. Final result: `[[-1, -1, 2], [-1, 0, 1]]`.

## Complexity

- time **O(n²)**
- space **O(1)** extra (excluding the output and the sort's own auxiliary space — Python's Timsort can use up to O(n))

## Pitfalls
- Forgetting to **sort first** — without sort, you can't skip duplicates cleanly and the two-pointer step doesn't apply.
- Skipping duplicates only on `i` but not on `l` and `r` — you'll emit duplicate triplets.
- Not breaking when `arr[i] > 0` — a cheap early exit: once the anchor is positive, every value after it is too, so no triplet can sum to 0.
- Returning indices instead of values when the problem asks for values, or vice versa.
- Using a hash-set for dedup of triplets — works, but O(n²) extra space; the sort-then-skip approach is cleaner.
