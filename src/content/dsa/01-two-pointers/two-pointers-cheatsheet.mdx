## Interview-ready explanation

Two pointers means walking two indices over a sequence so that each step rules out candidates for good, which turns an O(n²) scan of all pairs into O(n). There are two main forms. Converging pointers start at both ends of a sorted array and move inward based on a comparison, as in Two Sum II, 3Sum, and Container With Most Water. Slow/fast pointers move in the same direction, with fast reading and slow writing, for in-place dedupe, partitioning, or compaction. The key is an invariant about what is already resolved, so each move is provably safe. The result is O(n) time (O(n log n) if you must sort first) and O(1) extra space.

**One-liner:** Two indices move under an invariant so every step safely discards candidates, giving O(n) time and O(1) space on sorted or in-place array problems.

## Trigger
**You see in the problem:** "sorted array + pair/triplet with sum X", "in-place remove/dedupe", "palindrome check", "two walls / heights → area or volume", "partition by predicate".

**Reach for this pattern when:**
- Input is **sorted** (or you can sort it) and the question is about pairs/triplets.
- You must operate **in place** with O(1) extra space.
- A **symmetric** property — palindrome, reverse, equality from both ends.
- Two boundary values define an **area / capacity** (Container, Trapping Rain).

**Don't reach for it when:**
- Order matters and you can't sort (would destroy the answer's index).
- You need every contiguous subarray's stat — that's sliding window.
- The pair condition isn't monotone in pointer movement (no clean "move which side" rule).

## The mental model
Two indices walk the array under an **invariant**: everything outside `[l, r]` (converging) or before `slow` (partitioning) is already resolved. Each step inspects the two values, makes **one decision** — advance `l`, advance `r`, or write+advance — and the search space shrinks by 1. O(n) total because each pointer moves monotonically.

```cpp
// Converging pointers (sorted array, find pair)
vector<int> twoSumSorted(const vector<int>& arr, int target) {
    int l = 0, r = (int)arr.size() - 1;
    while (l < r) {
        int s = arr[l] + arr[r];
        if (s == target) return {l, r};
        else if (s < target) ++l;  // need bigger -> move left side up
        else --r;                  // need smaller -> move right side down
    }
    return {-1, -1};
}

// Slow/fast partition (in-place dedupe / move zeros)
int removeDups(vector<int>& arr) {
    int slow = 0;
    for (int fast = 0; fast < (int)arr.size(); ++fast) {
        if (fast == 0 || arr[fast] != arr[slow - 1]) {
            arr[slow] = arr[fast];
            ++slow;
        }
    }
    return slow;  // length of unique prefix
}
```

```java
class Solution {
    // Converging pointers (sorted array, find pair)
    static int[] twoSumSorted(int[] arr, int target) {
        int l = 0, r = arr.length - 1;
        while (l < r) {
            int s = arr[l] + arr[r];
            if (s == target) return new int[] {l, r};
            else if (s < target) l++;  // need bigger -> move left side up
            else r--;                  // need smaller -> move right side down
        }
        return new int[] {-1, -1};
    }

    // Slow/fast partition (in-place dedupe / move zeros)
    static int removeDups(int[] arr) {
        int slow = 0;
        for (int fast = 0; fast < arr.length; fast++) {
            if (fast == 0 || arr[fast] != arr[slow - 1]) {
                arr[slow] = arr[fast];
                slow++;
            }
        }
        return slow;  // length of unique prefix
    }
}
```

```python
# Converging pointers (sorted array, find pair)
def two_sum_sorted(arr, target):
    l, r = 0, len(arr) - 1
    while l < r:
        s = arr[l] + arr[r]
        if s == target: return [l, r]
        elif s < target: l += 1     # need bigger -> move left side up
        else:            r -= 1     # need smaller -> move right side down
    return [-1, -1]

# Slow/fast partition (in-place dedupe / move zeros)
def remove_dups(arr):
    slow = 0
    for fast in range(len(arr)):
        if fast == 0 or arr[fast] != arr[slow - 1]:
            arr[slow] = arr[fast]
            slow += 1
    return slow  # length of unique prefix
```

## Complexity
- Time: **O(n)** (or O(n log n) if you have to sort first)
- Space: **O(1)**

## Variants in this pattern
1. **Converging from ends** — sorted array + pair sum. `l++`/`r--` based on compare.
2. **Slow/fast partition** — in-place write head + scan head.
3. **Same-direction (sliding-like)** — both start at 0, fast races ahead.
4. **Triplet sweep (3Sum)** — fix one element, two-pointer the rest. O(n²).
5. **Running max from both ends** — two pointers with a running max on each side, which replaces precomputed prefix-max and suffix-max arrays (trapping rain water).
6. **Dutch national flag** — three pointers, partition into &lt;pivot / =pivot / &gt;pivot.

- [LC 167 — Two Sum II (Sorted)](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/) (Med) — canonical converge from ends.
- [LC 26 — Remove Duplicates from Sorted Array](https://leetcode.com/problems/remove-duplicates-from-sorted-array/) (Easy) — slow/fast write head.
- [LC 283 — Move Zeroes](https://leetcode.com/problems/move-zeroes/) (Easy) — slow points to next non-zero slot.
- [LC 11 — Container With Most Water](https://leetcode.com/problems/container-with-most-water/) (Med) — always move the shorter wall.
- [LC 15 — 3Sum](https://leetcode.com/problems/3sum/) (Med) — fix `i`, two-pointer on `i+1..n-1`; skip dupes.
- [LC 42 — Trapping Rain Water](https://leetcode.com/problems/trapping-rain-water/) (Hard) — two pointers with running max on each side.
- [LC 125 — Valid Palindrome](https://leetcode.com/problems/valid-palindrome/) (Easy) — converge, skip non-alphanum.

## Common bugs / pitfalls
- **Off-by-one on the while condition**: `l < r` vs `l <= r`. For pair-search use `<` (pair needs two distinct indices); for binary-style scans `<=`.
- **3Sum duplicates**: after a match, advance `l` *and* `r` past equal values; also skip duplicate `i` at the outer loop.
- **Moving the wrong pointer** in Container — you must move the *shorter* side; moving the taller can never improve area.
- **Forgetting to sort** when the problem allows it — without sort, converging logic breaks.
- **Slow/fast off-by-one**: in the skeleton above, `slow` is the *next* write index, so the length is `slow`. If your `slow` points at the *last written* slot (as on the Remove Duplicates page), the length is `slow + 1`. Know which convention you are using.
