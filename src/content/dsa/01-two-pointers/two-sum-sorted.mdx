## Problem
Given a **sorted** array and a target `T`, return the indices of two elements that sum to `T` (or report that none exist). O(1) extra space.

## Interview-ready explanation

This is converging two pointers on a sorted array. I put l at the start and r at the end and look at s = arr[l] + arr[r]. If s equals the target I return the pair. If s is too small, arr[l] cannot pair with anything, since arr[r] is the largest value left, so I move l right. If s is too large, arr[r] cannot pair with anything, so I move r left. Each step discards one element for good, so it is O(n) time and O(1) space; the unsorted version needs a hash map with O(n) space instead.

**One-liner:** On a sorted array, move l right when the sum is too small and r left when it is too large, discarding one element per step; O(n) time, O(1) space.

## Intuition
`arr[r]` is the largest value still in play, so `arr[l] + arr[r]` is the biggest sum `l` can make. If that is `< T`, every pair using `l` underflows, so `l` must move right. Symmetrically, if the sum overflows, `r` must move left. Each move discards a whole row or column of candidate pairs, so the algorithm visits at most `n` pointer positions total. The invariant: every pair we've skipped is provably not the answer.

## Algorithm
1. Start `l = 0`, `r = n - 1`.
2. Compute `s = arr[l] + arr[r]`.
3. If `s == T`, return `(l, r)`.
4. If `s < T`, increment `l`. Else decrement `r`.
5. Repeat until `l >= r`.

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& numbers, int target) {
        int l = 0, r = (int)numbers.size() - 1;
        while (l < r) {
            int s = numbers[l] + numbers[r];
            if (s == target) return {l + 1, r + 1};  // LeetCode 167 is 1-indexed
            if (s < target) ++l;
            else --r;
        }
        return {};  // no pair (LeetCode guarantees one exists)
    }
};
```

class Solution {

        int l = 0, r = numbers.length - 1;

            int s = numbers[l] + numbers[r];
            if (s == target) return new int[] {l + 1, r + 1};  // LeetCode 167 is 1-indexed

            else r--;

```python
def two_sum_sorted(arr, T):
    l, r = 0, len(arr) - 1
    while l < r:
        s = arr[l] + arr[r]
        if s == T:
            return (l, r)
        if s < T:
            l += 1
        else:
            r -= 1
    return None
```

## Walkthrough
On `[1, 3, 4, 6, 8, 11]`, target `10`:

- Step 1 — `l=0, r=5`: `1 + 11 = 12 > 10` → `r--`.
- Step 2 — `l=0, r=4`: `1 + 8 = 9 < 10` → `l++`.
- Step 3 — `l=1, r=4`: `3 + 8 = 11 > 10` → `r--`.
- Step 4 — `l=1, r=3`: `3 + 6 = 9 < 10` → `l++`.
- Step 5 — `l=2, r=3`: `4 + 6 = 10` → return `(2, 3)`.

- time **O(n)**

## Pitfalls
- Forgetting the array is **already sorted** — if it isn't, a hash-map solution in O(n) time / O(n) space is the right call.
- LeetCode 167 uses **1-indexed** return values — read the problem statement carefully.
- With duplicates and a "find all unique pairs" twist, advance `l` and `r` past equal neighbours after each match.
- For 3Sum / 4Sum, the outer loop fixes one (or two) elements; only the inner pair is two-pointer. Don't try to two-pointer everything at once.
