## Problem
Given a list of tasks (each labeled by a character) and a cooldown `n` (the same task can't run within `n` steps), find the minimum number of CPU cycles to finish all tasks. Two runs of the same task need **at least `n` cycles between them** (other tasks or idle), so a task run at time `t` can run again at `t + n + 1` at the earliest.

## Interview-ready explanation
This is a greedy simulation with a max-heap of task counts and a cooldown queue. Each cycle, I run the available task with the most remaining runs, because the most frequent task is the one that forces idle time; if it still has runs left, I park it in a FIFO queue tagged with the time its cooldown ends (current time + n). When that time is reached, it goes back into the heap, and if the heap is empty but the queue isn't, the CPU idles for that cycle. The cycle count when both are empty is the answer. It's O(T log K) time, where T is the number of cycles and K the number of distinct tasks, and O(K) space; the closed form `max((maxFreq − 1)·(n + 1) + tieCount, len(tasks))` gives the same answer in O(len(tasks)).

**One-liner:** Each cycle, run the most frequent available task from a max-heap and park it in a cooldown queue for n cycles, idling when nothing is available: O(T log K).

## Intuition
At each cycle, you want to run the task with the highest remaining count — that's a **max-heap on frequencies**. But you can't run a task again until its cooldown expires, so popped tasks go into a **cooldown queue** along with the time they become eligible. The invariant: **the heap holds every task that's available *now*; the queue holds every task waiting for its cooldown to lapse.**

## Algorithm
Count frequencies, build a max-heap. Each cycle: pop the most-frequent task (if any), decrement, and if it still has runs left, push `(t + n, count)` to the cooldown queue. At the end of cycle `t + n` that entry goes back into the heap, so the task can run again at `t + n + 1`. If the heap is empty, the CPU idles. Stop when both structures are empty.

```cpp
class Solution {
public:
    int leastInterval(vector<char>& tasks, int n) {
        unordered_map<char, int> freq;
        for (char c : tasks) ++freq[c];
        priority_queue<int> heap;          // max-heap of remaining counts
        for (auto& [task, c] : freq) heap.push(c);
        queue<pair<int, int>> q;           // (ready_time, count)
        int t = 0;
        while (!heap.empty() || !q.empty()) {
            ++t;
            if (!heap.empty()) {
                int cnt = heap.top() - 1;  // one less remaining
                heap.pop();
                if (cnt > 0) q.push({t + n, cnt});
            }
            if (!q.empty() && q.front().first == t) {
                heap.push(q.front().second);
                q.pop();
            }
        }
        return t;
    }
};
```

```java
class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char c : tasks) freq[c - 'A']++;
        PriorityQueue<Integer> heap = new PriorityQueue<>(Collections.reverseOrder());  // max-heap
        for (int c : freq) if (c > 0) heap.offer(c);
        Deque<int[]> queue = new ArrayDeque<>();  // {ready_time, count}
        int t = 0;
        while (!heap.isEmpty() || !queue.isEmpty()) {
            t++;
            if (!heap.isEmpty()) {
                int cnt = heap.poll() - 1;  // one less remaining
                if (cnt > 0) queue.offer(new int[] {t + n, cnt});
            }
            if (!queue.isEmpty() && queue.peek()[0] == t) {
                heap.offer(queue.poll()[1]);
            }
        }
        return t;
    }
}
```

```python
import heapq
from collections import Counter, deque

def least_interval(tasks, n):
    heap = [-c for c in Counter(tasks).values()]
    heapq.heapify(heap)
    queue = deque()   # (ready_time, neg_count)
    t = 0
    while heap or queue:
        t += 1
        if heap:
            cnt = heapq.heappop(heap) + 1   # one less remaining
            if cnt < 0:
                queue.append((t + n, cnt))
        if queue and queue[0][0] == t:
            heapq.heappush(heap, queue.popleft()[1])
    return t
```

## Walkthrough
Example: `tasks = ['A','A','A','B','B','B']`, `n = 2`. Initial heap = `[A×3, B×3]`. Expected answer: **8** (`A B idle A B idle A B`).

1. **t=1: run A.** Pop A (3 left → 2) and park `(ready@3, A×2)`. **t=2: run B**, park `(ready@4, B×2)`. Heap is now empty.
2. **t=3: idle.** Nothing in the heap, so the CPU idles. At the end of t=3, `A×2@3` is released back into the heap.
3. **t=4: run A**, park `(ready@6, A×1)`; at the end of t=4, `B×2@4` is released. **t=5: run B**, park `(ready@7, B×1)`.
4. **t=6: idle** again; at the end of t=6, `A×1` is released. **t=7: run A** — its count hits 0, so it is not parked; `B×1@7` is released.
5. **t=8: run B.** Heap and queue are both empty → return **8**. Check with the closed form: `(maxFreq − 1)·(n + 1) + tieCount = 2·3 + 2 = 8`.

## Complexity

- time **O(T log K)**
- space **O(K)**

Where T is the total cycles and K is the number of distinct tasks (≤ 26 for letters → effectively O(T)).

## Pitfalls
- **Idle cycles count** — when the heap is empty but the queue isn't, the CPU still ticks forward.
- **Closed-form shortcut** — `max((maxFreq - 1) * (n + 1) + tieCount, len(tasks))` gives the answer in O(len(tasks)). Mention it once you've coded the heap version.
- **Cooldown queue is FIFO** — entries become eligible in insertion order because each lasts the same `n` cycles.
- **Don't push back zero-count tasks** — they're done. Pushing them back wastes O(log K) per push, and a leftover zero-count entry can later be "run" as an extra cycle, inflating the answer.
- For **task-with-deadline / per-task cost** variants, the heap key changes but the queue mechanism stays the same.
