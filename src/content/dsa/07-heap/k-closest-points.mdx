## Problem
Given a list of 2D points, return the K closest to the origin (Euclidean distance).

## Interview-ready explanation
This is the top-K heap pattern. I want the K smallest distances, so I keep a max-heap of size K keyed on squared distance, x² + y². I skip the square root because it doesn't change the order. In Python I push the negated distance, since `heapq` is a min-heap. For each point I push it, and if the heap grows past K, I pop the root, which is the farthest point I'm holding. After the scan, the heap holds the K closest points. Each point costs O(log K), so it's O(n log K) time and O(K) space. Quickselect is an O(n) average-case alternative.

**One-liner:** Keep a size-K max-heap on squared distance, evicting the farthest whenever it exceeds K: O(n log K) time, O(K) space.

## Intuition
Same template as top-K largest, just keyed differently. We want the K **smallest** distances, so we keep a **max-heap of size K**: the heap's root is the *worst* (farthest) of our current K candidates. Any incoming point closer than the root displaces it. The invariant: **the heap holds the K closest points seen so far, and its root is the K-th closest (i.e., the farthest of the keepers).**

## Algorithm
Push every point with key = squared distance. Whenever the heap exceeds K, pop the worst. No need to square-root — squared distance preserves ordering.

```cpp
class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        // max-heap on (dist², -x, -y): the root is the farthest point (same tie-break as Python)
        priority_queue<array<int, 3>> heap;
        for (auto& p : points) {
            int x = p[0], y = p[1];
            int d2 = x * x + y * y;
            heap.push({d2, -x, -y});
            if ((int)heap.size() > k)
                heap.pop();                // evict the farthest of the top-(K+1)
        }
        vector<vector<int>> res;
        while (!heap.empty()) {
            auto top = heap.top();
            heap.pop();
            res.push_back({-top[1], -top[2]});
        }
        return res;
    }
};
```

```java
class Solution {
    public int[][] kClosest(int[][] points, int k) {
        // max-heap on dist², ties: smaller x then smaller y on top (same tie-break as Python)
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) ->
            a[0] != b[0] ? Integer.compare(b[0], a[0])
            : a[1] != b[1] ? Integer.compare(a[1], b[1]) : Integer.compare(a[2], b[2]));
        for (int[] p : points) {
            int x = p[0], y = p[1];
            int d2 = x * x + y * y;
            heap.offer(new int[] {d2, x, y});
            if (heap.size() > k)
                heap.poll();               // evict the farthest of the top-(K+1)
        }
        int[][] res = new int[heap.size()][];
        int i = 0;
        for (int[] e : heap) res[i++] = new int[] {e[1], e[2]};
        return res;
    }
}
```

```python
import heapq

def k_closest(points, k):
    heap = []  # max-heap: store (-dist², point)
    for x, y in points:
        d2 = x * x + y * y
        heapq.heappush(heap, (-d2, x, y))
        if len(heap) > k:
            heapq.heappop(heap)        # evict the farthest of the top-(K+1)
    return [[x, y] for _, x, y in heap]
```

## Walkthrough
Example: 8 points `[(1,3), (-2,2), (5,8), (0,1), (3,-1), (-3,4), (2,2), (6,-2)]` with squared distances `[10, 8, 89, 1, 10, 25, 8, 40]`. `K = 3`.

1. **Fill the heap to K.** Push points 0, 1, 2 (d² = 10, 8, 89). Max-heap = `{89, 10, 8}` with root = 89 (the farthest).
2. **Point 3 (d²=1) displaces the farthest.** Push (1) → size 4 > 3 → pop the root **89**. Heap = `{10, 8, 1}`.
3. **Points 4 and 5.** d²=10 ties the root; pushing then popping removes one of the two 10s (which one depends on the tuple tie-break), so the kept distances stay `{10, 8, 1}`. d²=25 is worse than the current root 10 → push then pop evicts 25 immediately. Heap stays `{10, 8, 1}`.
4. **Point 6 (d²=8) bumps a 10.** Push 8 → root becomes 10, pop it. Heap = `{8, 8, 1}`. Point 7 (d²=40) is worse than 8 → pop it back out. Heap unchanged.
5. **End.** Survivors are indices `{1, 3, 6}` = `(-2,2), (0,1), (2,2)` — the 3 closest points to the origin.

## Complexity

- time **O(n log K)**
- space **O(K)**

## Pitfalls
- **Use squared distance** — no `sqrt`, no float drift, same ordering.
- **Max-heap for closest** — same counter-intuitive flip as top-K largest. Negate keys for `heapq`.
- **Quickselect** is O(n) average and beats heap when K is large; know both.
- **Ties** — when two points have equal distance, problems usually allow any order. Confirm with the interviewer.
- **3D / higher dims** — same template, just `d² = sum(c² for c in coords)`.
