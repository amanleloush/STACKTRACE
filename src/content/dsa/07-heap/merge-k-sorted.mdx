## Problem
Merge K sorted linked lists (or arrays) into one sorted output.

## Interview-ready explanation
This is a K-way merge with a min-heap. The next output element is always the smallest of the K current heads, so I put each non-empty list's first element in a min-heap as `(value, list index, position)`. The list index breaks ties, so Python never has to compare the nodes themselves. I repeatedly pop the smallest, append it to the output, and push the next element from the same list if there is one. The heap never holds more than K entries, so each of the N total elements costs O(log K): O(N log K) time and O(K) extra space.

**One-liner:** Min-heap of the K list heads; pop the smallest, then push its successor from the same list: O(N log K) time, O(K) space.

## Intuition
At any moment, the next element of the merged output must be the smallest among the **current heads** of all K lists. A min-heap of those K heads gives the next element in O(log K), and after popping we push the popped head's successor. The invariant: **the heap always contains at most one live pointer per list, namely the smallest unmerged element of that list.**

## Algorithm
Seed the heap with `(value, list_index, position)` for every non-empty head (for linked lists, store the node instead of the position). Loop: pop the smallest, append it to the result, and if the popped node has a successor, push that successor. Stop when the heap is empty.

```cpp
class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        // (val, list_idx); cur[i] is list i's current head, so nodes are never compared
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> heap;
        vector<ListNode*> cur(lists.begin(), lists.end());
        for (int i = 0; i < (int)cur.size(); ++i) {
            if (cur[i]) heap.push({cur[i]->val, i});
        }
        ListNode dummy;
        ListNode* tail = &dummy;
        while (!heap.empty()) {
            int i = heap.top().second;
            heap.pop();
            tail->next = cur[i];
            tail = tail->next;
            cur[i] = cur[i]->next;
            if (cur[i]) heap.push({cur[i]->val, i});
        }
        tail->next = nullptr;
        return dummy.next;
    }
};
```

```java
class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        // {val, list_idx}; cur[i] is list i's current head, so nodes are never compared
        PriorityQueue<int[]> heap = new PriorityQueue<>(
            (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0]) : Integer.compare(a[1], b[1]));
        ListNode[] cur = lists.clone();
        for (int i = 0; i < cur.length; i++) {
            if (cur[i] != null) heap.offer(new int[] {cur[i].val, i});
        }
        ListNode dummy = new ListNode();
        ListNode tail = dummy;
        while (!heap.isEmpty()) {
            int i = heap.poll()[1];
            tail.next = cur[i];
            tail = tail.next;
            cur[i] = cur[i].next;
            if (cur[i] != null) heap.offer(new int[] {cur[i].val, i});
        }
        tail.next = null;
        return dummy.next;
    }
}
```

```python
import heapq

def merge_k_sorted(lists):
    heap, out = [], []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(heap, (lst[0], i, 0))  # (val, list_idx, pos)
    while heap:
        val, i, j = heapq.heappop(heap)
        out.append(val)
        if j + 1 < len(lists[i]):
            heapq.heappush(heap, (lists[i][j + 1], i, j + 1))
    return out
```

## Walkthrough
Example: `lists = [[1, 4, 7], [2, 5, 8], [3, 6, 9]]`.

1. **Seed.** Push each list's head into a min-heap of `(val, list_idx, pos)`: heap = `[(1, L0, 0), (2, L1, 0), (3, L2, 0)]`, output empty.
2. **Pop 1, push 4.** Pop root `(1, L0, 0)` → `out = [1]`. List 0 has a successor → push `(4, L0, 1)`. Heap = `[(2, L1, 0), (3, L2, 0), (4, L0, 1)]`.
3. **Pop 2, push 5.** Root is `(2, L1, 0)` → `out = [1, 2]`, push `(5, L1, 1)`. Heap = `[(3, L2, 0), (4, L0, 1), (5, L1, 1)]`.
4. **Keep popping the next-smallest.** Repeating the pop-then-push step gives `out = [1, 2, 3, 4, 5, 6, 7, 8, 9]`. Each list's pointer advances exactly when its head was the latest pop.
5. **End.** Heap drains to empty after all 9 values are emitted; output is the fully merged sorted list.

## Complexity

- time **O(N log K)**
- space **O(K)**

Where N is the total number of elements across all K lists.

## Pitfalls
- **Tuples must be comparable** — for linked-list nodes, include a tiebreaker like the list index so Python doesn't try to compare nodes.
- **Don't reseed** — only push the *successor* of the popped element, not all heads on every iteration.
- **Divide-and-conquer pairwise merge** is O(N log K) too and, for linked lists merged iteratively, uses O(1) extra space — prefer it when memory matters.
- **Empty input lists** — skip them at seed time or guard inside the loop.
- For **streaming** K-way merge (infinite lists), generators + heap let you yield lazily.
