## Problem
Given symbol frequencies, build a prefix-free binary code that minimizes total encoded length: `sum(freq[c] · depth[c])`.

## Interview-ready explanation
This is Huffman coding, a greedy algorithm built on a min-heap. The key insight is that some optimal tree puts the two least-frequent symbols as siblings at the deepest level, and merging them into one node whose frequency is their sum leaves a smaller problem of the same shape. So I put all frequencies in a min-heap, repeatedly pop the two smallest, add their sum to the total cost, and push the sum back, until one node (the root) remains. The total cost equals the sum of `freq × depth` over all symbols. With n symbols that is n − 1 merges at O(log n) each, so O(n log n) time and O(n) space.

**One-liner:** Huffman coding repeatedly merges the two lowest-frequency nodes from a min-heap into a parent until one tree remains, giving an optimal prefix-free code in O(n log n).

## Intuition
Two observations drive the proof. **(1) Some optimal tree has the two least-frequent symbols as siblings at the deepest level** — take any optimal tree and swap them with the two deepest siblings; the total weighted depth can only stay the same or improve. (With ties, other optimal trees may place them differently.) **(2) After merging those two into a single "super-symbol" with frequency = sum, the residual problem is the same shape on one fewer leaf.** So a min-heap of frequencies, repeatedly extracting two and pushing their sum, builds an optimal tree from the leaves up. The shape of the tree records the code; the algorithm itself never tracks bits.

## Algorithm
```python
import heapq

def huffman_cost(freqs):
    heap = list(freqs)
    heapq.heapify(heap)
    total = 0
    while len(heap) > 1:
        a = heapq.heappop(heap)
        b = heapq.heappop(heap)
        total += a + b              # contributes to depth of both
        heapq.heappush(heap, a + b)
    return total
```

## Walkthrough
Example: symbol frequencies `a:5, b:9, c:12, d:13, e:16, f:45`. Min-heap holds the six leaves.

1. **Merge the two smallest leaves.** Pop `a:5`, then pop `b:9`. Create parent node with freq `5 + 9 = 14`, push back. Heap = `[c:12, d:13, 14, e:16, f:45]`.
2. **Merge 12 and 13.** Pop `c:12`, pop `d:13`. New parent freq `25`, push. Heap = `[14, e:16, 25, f:45]`.
3. **Merge 14 and 16.** Pop the freshly merged 14-node, pop `e:16`. New parent freq `30`, push. Heap = `[25, 30, f:45]`.
4. **Merge 25 and 30.** Pop them, create parent freq `55`, push. Heap = `[f:45, 55]`.
5. **Final merge → root.** Pop `f:45`, pop 55 → root has freq `100`. Heap collapses to a single node — the Huffman tree is complete. Total weighted path length = `14 + 25 + 30 + 55 + 100 = 224`.

## Pitfalls
- Popping only one node per round, or pushing back **before** both pops — every round must pop exactly two and push their sum.
- Using a max-heap by accident (negation flip) — Python's `heapq` is min by default; Java's `PriorityQueue` is also a min-heap by default, so don't pass a reverse comparator.
- For ties, the tree shape isn't unique but the cost is — don't assert specific codes in tests.
- Single-symbol input: cost is 0 (or 1 if the problem demands at least one bit per symbol — check the spec).
- Missing the disguise — LC 1167 (Connect Sticks) is exactly this merge-two-smallest loop; other heap greedies (2208, 1675) reuse the pop-the-extreme idea with different rules.
