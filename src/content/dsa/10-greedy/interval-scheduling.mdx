## Problem
Given intervals, merge all overlapping ones into the smallest set of disjoint intervals that covers the same points.

## Interview-ready explanation
This is the merge-intervals sweep. The key insight is that once the intervals are sorted by start, an interval can only overlap the one I am currently building, so a single running end is all the state I need. I sort by start, then for each interval: if its start is at or before the current end, I extend the end to the larger of the two ends; otherwise I close the current interval and start a new one. Sorting dominates, so it is O(n log n) time and O(n) space for the output.

**One-liner:** Sort intervals by start, then sweep once, extending the last merged interval when the next one starts at or before its end and starting a new one otherwise, in O(n log n).

## Intuition
Sort by **start time**. Sweep left to right keeping one "active" interval `[s, e]`. For each new `[s', e']`: if `s' ≤ e`, they overlap — extend `e = max(e, e')`. Otherwise the active interval is done; push it and start a new one with `[s', e']`. The proof: after sorting by start, every later interval starts at or after the active one, so an overlap can only push the right end out — a single "running end" is all you need. Sibling sweeps over sorted intervals answer room-count (with a min-heap of end times), non-overlap count, and intersections.

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[0] < b[0]; });
        vector<vector<int>> out;
        for (auto& iv : intervals) {
            int s = iv[0], e = iv[1];
            if (!out.empty() && s <= out.back()[1]) {
                out.back()[1] = max(out.back()[1], e);
            } else {
                out.push_back({s, e});
            }
        }
        return out;
    }
};
```

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> out = new ArrayList<>();
        for (int[] iv : intervals) {
            int s = iv[0], e = iv[1];
            if (!out.isEmpty() && s <= out.get(out.size() - 1)[1]) {
                int[] last = out.get(out.size() - 1);
                last[1] = Math.max(last[1], e);
            } else {
                out.add(new int[] {s, e});
            }
        }
        return out.toArray(new int[0][]);
    }
}
```

```python
def merge(intervals):
    intervals.sort(key=lambda x: x[0])

            out[-1][1] = max(out[-1][1], e)

    return out
```

## Walkthrough
Example: `intervals = [[1,3], [2,6], [8,10], [15,18]]` (already sorted by start).

1. **Start.** `out = []`. Take `[1, 3]`: output is empty → **append**. `out = [[1, 3]]`.
2. **`[2, 6]` overlaps.** `2 ≤ out[-1].end = 3` → **merge**: extend last end to `max(3, 6) = 6`. `out = [[1, 6]]`.
3. **`[8, 10]` is disjoint.** `8 > 6` → **append**. `out = [[1, 6], [8, 10]]`.
4. **`[15, 18]` is disjoint.** `15 > 10` → **append**. `out = [[1, 6], [8, 10], [15, 18]]`.
5. **End.** Three merged intervals returned — the input's two overlapping intervals collapsed into `[1, 6]`.

## Pitfalls
- Sorting by end works for activity selection but **breaks** merging — `[[2,3],[1,10]]` sorted by end gives `[2,10]` instead of `[1,10]`.
- Touching vs overlapping: `[1,3]` and `[3,5]` — decide whether to merge based on the problem statement (LC 56 merges them).
- For "meeting rooms II", don't try to merge — use a min-heap of end times instead.
- For inserting a new interval (LC 57), don't re-sort; do a three-phase sweep (before, overlap-and-extend, after).
- Mutating the input list while iterating — make `out` separate or work on indices.
