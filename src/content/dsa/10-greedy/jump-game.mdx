## Problem
Given `nums` where `nums[i]` is the max jump from index `i`, can you reach the last index? (And for Jump Game II, in how few jumps?)

## Interview-ready explanation
This is a greedy farthest-reach sweep. For Jump Game I, I track `reach`, the farthest index reachable so far; at each index `i`, if `i > reach` I am stuck and return false, otherwise I update `reach = max(reach, i + nums[i])`. For Jump Game II, I treat it as BFS by levels without a queue: `end` marks the edge of what the current number of jumps can reach, and when `i` hits `end` I take one more jump and move `end` to the farthest index seen so far. Both run in O(n) time and O(1) space.

**One-liner:** Sweep left to right tracking the farthest reachable index; you fail if i ever passes it, and for minimum jumps you count a jump each time i reaches the current level's boundary, in O(n) time and O(1) space.

## Intuition
You don't need to enumerate paths — just track the **farthest index reachable so far**. Sweep left to right; at each `i ≤ reach`, update `reach = max(reach, i + nums[i])`. If `i` ever moves past `reach` (because `reach` stalled before index `n-1`), you're stuck. For Jump Game II, the trick is to think in **levels**: maintain a current jump's right boundary; when `i` hits it, you must have used another jump, and the new boundary is the farthest reached so far. This is BFS on indices without the queue.

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int reach = 0;
        for (int i = 0; i < (int)nums.size(); ++i) {
            if (i > reach) return false;
            reach = max(reach, i + nums[i]);
        }
        return true;
    }

    int jump(vector<int>& nums) {  // assumes the last index is reachable (LC 45 guarantees it)
        int jumps = 0, end = 0, farthest = 0;
        for (int i = 0; i < (int)nums.size() - 1; ++i) {
            farthest = max(farthest, i + nums[i]);
            if (i == end) {  // consumed current jump
                ++jumps;
                end = farthest;
            }
        }
        return jumps;
    }
};
```

```python
def can_jump(nums):
    reach = 0
    for i, v in enumerate(nums):
        if i > reach:
            return False
        reach = max(reach, i + v)
    return True

def jump_ii(nums):                  # assumes the last index is reachable (LC 45 guarantees it)
    jumps = end = farthest = 0
    for i in range(len(nums) - 1):
        farthest = max(farthest, i + nums[i])
        if i == end:                # consumed current jump
            jumps += 1
            end = farthest
    return jumps
```

## Walkthrough
1. `nums = [2,3,1,1,4]`. `reach = 0`.
2. `i=0, v=2` → `reach = max(0, 0+2) = 2`.
3. `i=1, v=3` → `reach = max(2, 1+3) = 4`. Already covers last index.
4. Loop completes without `i > reach`. Return **True**.
5. Jump II on same array: at `i=0`, farthest=2, end=0 → jump (jumps=1, end=2). At `i=1`, farthest=4. At `i=2`, end consumed → jump (jumps=2, end=4). Answer = 2.

time **O(n)** · space **O(1)**

## Pitfalls
- Updating `reach` for indices `i > reach` — you can't stand there, so you can't jump from there.
- For Jump Game II, looping to `n` instead of `n-1`: the last index doesn't trigger another jump.
- Off-by-one when `nums[i] = 0` — you stall, not fail, unless `i == reach < n-1`.
- Confusing "max jump = `nums[i]`" with "exact jump" — Jump Game IV uses different rules.
- Trying DP first; the O(n²) DP times out on large inputs where greedy is the intended solution.
