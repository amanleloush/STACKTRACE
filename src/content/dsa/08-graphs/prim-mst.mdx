## Problem
Given a weighted undirected graph, find a **minimum spanning tree** — same goal as Kruskal, different growth strategy.

## Interview-ready explanation
This is Prim's algorithm, a greedy MST algorithm that grows one tree outward from a start vertex. The key insight is the cut property: the cheapest edge crossing from the tree to the rest of the graph is always safe to add. I keep a min-heap of `(edge_weight, vertex)` for edges leaving the tree, pop the cheapest, skip it if that vertex is already in the tree (a stale entry), and otherwise add the vertex, add the weight, and push all its edges to vertices not yet in the tree. With a binary heap this runs in O(E log V) time and O(V + E) space; on a dense graph an adjacency-matrix version without a heap runs in O(V²).

**One-liner:** Prim grows the MST from one vertex by repeatedly taking the cheapest edge leaving the tree from a min-heap, like Dijkstra keyed on edge weight, in O(E log V).

## Intuition
Grow the MST node by node. Start from any vertex; repeatedly add the **cheapest edge that connects an in-tree node to an out-of-tree node**. A min-heap of crossing edges makes this efficient. The invariant: **the tree-so-far is always a subtree of *some* MST** (cut property again). Prim is essentially Dijkstra where the key is the edge weight to the frontier, not the cumulative distance from a source.

## Algorithm
Maintain a `in_tree` set and a min-heap of `(edge_weight, neighbor)` for edges crossing the cut. Pop the cheapest crossing edge; if its neighbor isn't in the tree yet, add it and push all of its outgoing edges.

```cpp
int prim(int n, const vector<vector<pair<int, int>>>& graph, int start = 0) {
    vector<bool> in_tree(n, false);
    // min-heap of (edge weight, vertex)
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> heap;
    heap.push({0, start});
    int total = 0, taken = 0;
    while (!heap.empty() && taken < n) {
        auto [w, u] = heap.top();
        heap.pop();
        if (in_tree[u]) continue;
        in_tree[u] = true;
        total += w;
        taken += 1;
        for (auto [v, weight] : graph[u]) {
            if (!in_tree[v]) heap.push({weight, v});
        }
    }
    return taken == n ? total : -1;  // -1 if disconnected
}
```

```java
class Solution {
    static int prim(int n, List<List<int[]>> graph, int start) {
        boolean[] inTree = new boolean[n];
        // min-heap of {edge weight, vertex}
        PriorityQueue<int[]> heap = new PriorityQueue<>(
            (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0]) : Integer.compare(a[1], b[1]));
        heap.add(new int[] {0, start});
        int total = 0, taken = 0;
        while (!heap.isEmpty() && taken < n) {
            int[] top = heap.poll();
            int w = top[0], u = top[1];
            if (inTree[u]) continue;
            inTree[u] = true;
            total += w;
            taken += 1;
            for (int[] e : graph.get(u)) {
                int v = e[0], weight = e[1];
                if (!inTree[v]) heap.add(new int[] {weight, v});
            }
        }
        return taken == n ? total : -1;  // -1 if disconnected
    }
}
```

```python
import heapq

def prim(n, graph, start=0):
    in_tree = [False] * n
    heap = [(0, start)]
    total, taken = 0, 0
    while heap and taken < n:
        w, u = heapq.heappop(heap)
        if in_tree[u]:
            continue
        in_tree[u] = True
        total += w
        taken += 1
        for v, weight in graph[u]:
            if not in_tree[v]:
                heapq.heappush(heap, (weight, v))
    return total if taken == n else -1     # -1 if disconnected
```

## Walkthrough
Example: 6 nodes `A–F`, edges `A-B(4), A-D(1), B-C(3), B-E(2), C-F(5), D-E(6), E-F(7), B-D(8)`. Start = A.

1. **Seed.** `visited = {A}`; frontier (sorted) = `A-D(1), A-B(4)`.
2. **Absorb D.** Pop `A-D(1)` — D not visited, accept → MST += A-D. Push D's new crossings `D-E(6), B-D(8)`. Frontier = `A-B(4), D-E(6), B-D(8)`. Total = 1.
3. **Absorb B, then E.** Pop `A-B(4)` → accept; push `B-C(3), B-E(2)` (B-D is skipped because D is already in the tree). Frontier head is now `B-E(2)` — pop, accept E, push `E-F(7)`. Total = 1+4+2 = 7.
4. **Absorb C, then F.** Pop `B-C(3)` → accept C, push `C-F(5)`. Pop `C-F(5)` → accept F. Total = 7+3+5 = 15.
5. **End.** All 6 nodes visited; MST = `{A-D, A-B, B-E, B-C, C-F}`, weight **15**. The loop stops once `taken == n`; the leftover entries (`D-E(6)`, `E-F(7)`, `B-D(8)`) would hit in-tree endpoints and be discarded anyway.

## Complexity

time **O(E log V)** · space **O(V + E)**

With a Fibonacci heap, O(E + V log V). With an adjacency matrix and no heap, O(V²) — better for dense graphs.

## Pitfalls
- **Skip in-tree on pop** — like Dijkstra, you'll have stale heap entries. Discard if the target is already in the tree.
- **Disconnected graphs** — Prim from one start only covers one component. Loop over un-marked starts to get the forest.
- **Prim needs neighbor lookups** (an adjacency list, or a matrix for the O(V²) version); if you only have an edge list, Kruskal is more natural.
- **Dense vs sparse** — Prim with a matrix is O(V²) (no heap). For E ≈ V², that beats E log V.
- **Tie-breaking** — any choice among equal-cost crossing edges is optimal.
