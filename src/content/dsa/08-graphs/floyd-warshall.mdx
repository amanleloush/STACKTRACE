## Problem
Compute the shortest distance between **every pair** of nodes in a weighted graph (no negative cycles).

## Interview-ready explanation
Floyd-Warshall is dynamic programming for all-pairs shortest paths. I start with a V×V matrix: 0 on the diagonal, edge weights where edges exist, and infinity elsewhere. Then for each intermediate node k (the outermost loop), for every pair (i, j), I set `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`. After processing k, `dist[i][j]` is the shortest path that uses only nodes 0..k as intermediates, so after the last k it's the true shortest path. It handles negative edges, and a negative value on the diagonal means a negative cycle. It's O(V³) time and O(V²) space, which is fine for a few hundred nodes.

**One-liner:** Triple loop with the intermediate node k outermost, setting dist[i][j] to the smaller of itself and dist[i][k] + dist[k][j]: all-pairs shortest paths in O(V³) time, O(V²) space.

## Intuition
For every pair `(i, j)`, consider routes that may pass through an intermediate node `k`. If `dist[i][k] + dist[k][j] < dist[i][j]`, the route through `k` wins. Iterate `k` from 0 to V−1; after `k` is processed, **`dist[i][j]` is the shortest path using intermediates from `{0..k}` only**. After the full loop, you've allowed every node as an intermediate — done. That's the loop invariant.

## Algorithm
Init the distance matrix from the edge list (`dist[i][i] = 0`, edges fill in, rest infinity). Triple-loop: `k` outermost, then `i`, then `j`. Update on improvement.

```cpp
class Solution {
public:
    int findTheCity(int n, vector<vector<int>>& edges, int distanceThreshold) {
        const int INF = INT_MAX / 2;  // INF + INF still fits in an int
        vector<vector<int>> dist(n, vector<int>(n, INF));
        for (int i = 0; i < n; ++i) dist[i][i] = 0;
        for (auto& e : edges) {  // undirected: fill both directions
            int u = e[0], v = e[1], w = e[2];
            dist[u][v] = min(dist[u][v], w);
            dist[v][u] = min(dist[v][u], w);
        }
        for (int k = 0; k < n; ++k)
            for (int i = 0; i < n; ++i)
                for (int j = 0; j < n; ++j)
                    if (dist[i][k] + dist[k][j] < dist[i][j])
                        dist[i][j] = dist[i][k] + dist[k][j];
        // fewest cities within the threshold; ties go to the larger index
        int best = -1, bestCount = INT_MAX;
        for (int i = 0; i < n; ++i) {
            int count = 0;
            for (int j = 0; j < n; ++j)
                if (j != i && dist[i][j] <= distanceThreshold) ++count;
            if (count <= bestCount) {
                best = i;
                bestCount = count;
            }
        }
        return best;
    }
};
```

```java
class Solution {
    public int findTheCity(int n, int[][] edges, int distanceThreshold) {
        final int INF = Integer.MAX_VALUE / 2;  // INF + INF still fits in an int
        int[][] dist = new int[n][n];
        for (int i = 0; i < n; i++) {
            Arrays.fill(dist[i], INF);
            dist[i][i] = 0;
        }
        for (int[] e : edges) {  // undirected: fill both directions
            int u = e[0], v = e[1], w = e[2];
            dist[u][v] = Math.min(dist[u][v], w);
            dist[v][u] = Math.min(dist[v][u], w);
        }
        for (int k = 0; k < n; k++)
            for (int i = 0; i < n; i++)
                for (int j = 0; j < n; j++)
                    if (dist[i][k] + dist[k][j] < dist[i][j])
                        dist[i][j] = dist[i][k] + dist[k][j];
        // fewest cities within the threshold; ties go to the larger index
        int best = -1, bestCount = Integer.MAX_VALUE;
        for (int i = 0; i < n; i++) {
            int count = 0;
            for (int j = 0; j < n; j++)
                if (j != i && dist[i][j] <= distanceThreshold) count++;
            if (count <= bestCount) {
                best = i;
                bestCount = count;
            }
        }
        return best;
    }
}
```

```python
def floyd_warshall(n, edges):
    INF = float('inf')
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0
    for u, v, w in edges:
        dist[u][v] = min(dist[u][v], w)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist
```

```python driver
def find_the_city(n, edges, threshold):
    # LeetCode 1334: roads are undirected, so add each edge both ways.
    dist = floyd_warshall(n, edges + [[v, u, w] for u, v, w in edges])
    best, best_count = -1, float('inf')
    for i in range(n):
        count = sum(1 for j in range(n) if j != i and dist[i][j] <= threshold)
        if count <= best_count:     # ties go to the larger index

    return best
```

The C++ and Java versions solve LeetCode 1334 (Find the City), the canonical Floyd-Warshall problem: it builds the same all-pairs matrix, but its roads are undirected, so the first test runs the walkthrough's edges in both directions and prints a city index rather than the directed distance matrix the walkthrough builds.

## Walkthrough
Example: 4 nodes; edges `0→1(3), 0→3(7), 1→0(8), 1→2(2), 2→0(5), 2→3(1), 3→0(2)`.

1. **Init.** Diagonals = 0; direct edges filled; rest ∞.
2. **k=0.** Try every `(i,j)` via node 0: `1→0→3 = 8+7 = 15` updates `dist[1][3]` (was ∞); `2→0→1 = 5+3 = 8` updates `dist[2][1]`; `2→0→3 = 5+7 = 12` does **not** beat the direct `dist[2][3]=1`; `3→0→1 = 2+3 = 5` updates `dist[3][1]`.
3. **k=1.** Routes via node 1: `0→1→2 = 3+2 = 5` updates `dist[0][2]`; `3→1→2 = 5+2 = 7` updates `dist[3][2]`.
4. **k=2.** Routes via node 2: `0→2→3 = 5+1 = 6` beats `dist[0][3]=7`; `1→2→3 = 2+1 = 3` beats `dist[1][3]=15`; `1→2→0 = 2+5 = 7` beats `dist[1][0]=8`.
5. **k=3 → done.** Routes via node 3 close the loop (e.g. `1→3→0 = 3+2 = 5` beats `dist[1][0]=7`); after the k=3 sweep, the matrix holds all-pairs shortest paths: row 0 = `[0, 3, 5, 6]`, row 1 = `[5, 0, 2, 3]`, row 2 = `[3, 6, 0, 1]`, row 3 = `[2, 5, 7, 0]`.

## Complexity

time **O(V³)** · space **O(V²)**

## Pitfalls
- **`k` is the outer loop** — getting the loop order wrong silently produces wrong answers. Memorize: k, i, j.
- **Negative cycles** — check `dist[i][i] < 0` after the loop; a negative diagonal entry means node `i` lies on a negative cycle.
- **V³ is brutal** for V > ~500 — fall back to Dijkstra-per-source (O(V · (E + V) log V)) for sparse graphs.
- **Transitive closure** — use booleans and replace `min` with OR and `+` with AND: `reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])`. Same loop shape, gives reachability.
- **Path reconstruction** — store `next[i][j] = j` (initially) and update `next[i][j] = next[i][k]` on relaxation; walk `next` to rebuild.
