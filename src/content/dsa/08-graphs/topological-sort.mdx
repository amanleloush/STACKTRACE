## Problem
Given a directed acyclic graph (DAG), output a linear ordering of nodes such that every edge `u → v` has `u` before `v`. If the graph has a cycle, report it.

## Interview-ready explanation
This is topological sort with Kahn's algorithm, a BFS over in-degrees. The key insight is that a node with in-degree zero has no unmet prerequisites, so it can go next. I count in-degrees, put every zero-in-degree node in a queue, and repeatedly pop a node, append it to the output, and decrement its neighbors' in-degrees, enqueuing any that reach zero. If the output has fewer than V nodes, the leftover nodes are on or behind a cycle, so no valid order exists. It runs in O(V + E) time and O(V + E) space for the adjacency list and in-degree array.

**One-liner:** Kahn's algorithm repeatedly removes zero-in-degree nodes with a queue to build a topological order in O(V + E), and reports a cycle if fewer than V nodes come out.

## Intuition
A node is "ready" once all of its prerequisites have been emitted — i.e., when its **in-degree drops to zero**. Kahn's algorithm peels off zero-in-degree nodes one at a time, like leaves off a tree, decrementing in-degrees as it goes. The invariant: **at every step, the queue contains exactly the nodes whose prerequisites are all already emitted.** If the loop ends without visiting every node, the graph has a cycle: every leftover node is on a cycle or reachable from one.

## Algorithm
Build the in-degree map. Seed a queue with every zero-in-degree node. Pop, append to output, and decrement each neighbor's in-degree; when a neighbor hits zero, enqueue it. If the output length equals V, return it; otherwise the graph has a cycle.

```cpp
vector<int> topoSort(int n, const vector<vector<int>>& edges) {
    vector<vector<int>> g(n);
    vector<int> indeg(n, 0);
    for (auto& e : edges) {
        g[e[0]].push_back(e[1]);
        indeg[e[1]] += 1;
    }
    queue<int> q;
    for (int i = 0; i < n; ++i) {
        if (indeg[i] == 0) q.push(i);
    }
    vector<int> out;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        out.push_back(u);
        for (int v : g[u]) {
            indeg[v] -= 1;
            if (indeg[v] == 0) q.push(v);
        }
    }
    if ((int)out.size() == n) return out;
    return {};  // [] signals a cycle
}
```

```java
class Solution {
    static int[] topoSort(int n, int[][] edges) {
        List<List<Integer>> g = new ArrayList<>();
        for (int i = 0; i < n; i++) g.add(new ArrayList<>());
        int[] indeg = new int[n];
        for (int[] e : edges) {
            g.get(e[0]).add(e[1]);
            indeg[e[1]] += 1;
        }
        Deque<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            if (indeg[i] == 0) q.add(i);
        }
        int[] out = new int[n];
        int size = 0;
        while (!q.isEmpty()) {
            int u = q.poll();
            out[size++] = u;
            for (int v : g.get(u)) {
                indeg[v] -= 1;
                if (indeg[v] == 0) q.add(v);
            }
        }
        return size == n ? out : new int[0];  // [] signals a cycle
    }
}
```

```python
from collections import deque, defaultdict

def topo_sort(n, edges):
    g = defaultdict(list)
    indeg = [0] * n
    for u, v in edges:
        g[u].append(v)
        indeg[v] += 1
    q = deque(i for i in range(n) if indeg[i] == 0)
    out = []
    while q:
        u = q.popleft()
        out.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return out if len(out) == n else []   # [] signals a cycle
```

## Walkthrough
Example: `n = 6`, edges `[(5,2), (5,0), (4,0), (4,1), (2,3), (3,1)]`.

1. In-degrees: 0→2, 1→2, 2→1, 3→1, 4→0, 5→0. Queue starts with [4, 5].
2. Pop 4 → out=[4]. Decrement 0 (→1) and 1 (→1). Queue=[5].
3. Pop 5 → out=[4, 5]. Decrement 2 (→0) and 0 (→0); both enqueue. Queue=[2, 0].
4. Pop 2 → out=[4, 5, 2]. Decrement 3 (→0). Queue=[0, 3]. Pop 0 → out=[4, 5, 2, 0]; no outgoing edges.
5. Pop 3 → decrement 1 (→0). Pop 1 → out=[4, 5, 2, 0, 3, 1]. Length = 6 → done.

## Pitfalls
- **Cycle detection comes for free** — if `len(out) < n`, you have a cycle. Don't add a separate DFS pass.
- **Multiple valid orderings exist** — use a min-heap instead of a queue if the problem demands the lexicographically smallest.
- **DFS-based topo** (post-order + reverse) is equally valid and sometimes cleaner; know both.
- **Self-loops** count as a cycle (the node's in-degree is at least 1 and only the node itself could lower it, so it never reaches zero).
- **Disconnected DAG** — works fine; every connected component contributes its zero-in-degree nodes.
