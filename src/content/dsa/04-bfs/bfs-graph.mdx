## Problem
Given an undirected (or directed) graph and a start node `s`, compute the shortest distance from `s` to every reachable node — where every edge has weight 1.

## Interview-ready explanation

This is breadth-first search for single-source shortest paths in an unweighted graph. I set dist[start] = 0 and put start in a FIFO queue. Then I pop a node u, and for each neighbour v that has no distance yet, I set dist[v] = dist[u] + 1 and push v. The queue processes nodes in non-decreasing order of distance, so the first time a node is discovered it gets its shortest distance, and a dist map that doubles as the visited set is enough; no priority queue is needed. Each node is queued once and each edge is checked once (twice in an undirected graph), so it is O(V + E) time and O(V) space.

**One-liner:** BFS from the source with a queue, giving each newly discovered node its parent's distance plus one; O(V + E) shortest paths in unweighted graphs.

## Intuition
BFS explores nodes in **non-decreasing order of distance** from the source. The first time you discover (enqueue) a node, you've arrived via a shortest path — and you never need to re-enqueue it. This is why a `visited` set (or a distance map initialized to `-1`/`∞`) is enough; you don't need a priority queue like Dijkstra. The queue itself encodes the frontier of "currently expanding" nodes.

## Algorithm
1. Initialize `dist[s] = 0` and a queue containing `s`. All other nodes have `dist = ∞`.
2. While the queue is non-empty:
   - Pop `u`.
   - For each neighbour `v` of `u`: if `dist[v] == ∞`, set `dist[v] = dist[u] + 1` and enqueue `v`.
3. Return `dist`.

```python
from collections import deque

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist
```

## Walkthrough
Graph: `0 — 1 — 2`, `0 — 3`, `3 — 4`. Start at `0`:

1. Init: `dist = {0: 0}`, `q = [0]`.
2. Pop `0`. Visit `1`, `3`. `dist = {0:0, 1:1, 3:1}`, `q = [1, 3]`.
3. Pop `1`. Visit `2` (skip `0`). `dist = {0:0, 1:1, 3:1, 2:2}`, `q = [3, 2]`.
4. Pop `3`. Visit `4` (skip `0`). `dist = {..., 4:2}`, `q = [2, 4]`.
5. Pop `2`, `4`. No new neighbours. Done.

## Complexity

- time **O(V + E)**
- space **O(V)**

## Pitfalls
- **Marking visited on pop, not push.** This lets a node enter the queue multiple times, blowing up time complexity. Always mark when you enqueue.
- **Using a list as the queue** in Python — `list.pop(0)` is O(n). Always `collections.deque`.
- For **weighted graphs with unequal weights**, BFS can give wrong answers — switch to Dijkstra (or 0-1 BFS when weights are only 0 and 1).
- "Reachable" and "shortest path" are different questions, though BFS answers both. For a single target you can stop as soon as it is discovered; for distances to *every* node you must run until the queue is empty.
- For **bidirectional BFS**, keep a distance map for each side and expand one full level at a time. When a newly discovered node is already in the other side's map, the path length is the sum of its two distances; finish the current level and keep the minimum before stopping.
