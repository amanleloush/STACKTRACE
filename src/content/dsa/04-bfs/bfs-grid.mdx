## Problem
Given an `m × n` grid with open cells and obstacles, find the shortest path (in cell hops) from a start cell to a target cell — or compute distances to every reachable cell.

## Interview-ready explanation
I treat the grid as an implicit graph: each open cell is a node, and its up/down/left/right neighbours are its edges, generated on the fly with direction vectors. Because every move costs the same (one hop), breadth-first search (BFS) reaches cells in order of distance, so the first time I reach the target, that distance is the shortest. I push the start into a queue, mark it visited, then repeatedly pop a cell and enqueue every in-bounds, non-wall, unvisited neighbour at distance plus one, marking it visited as I enqueue it. Each cell enters the queue at most once, so time and space are both O(m·n).

**One-liner:** BFS over cells using direction vectors, marking visited on enqueue; the first time we pop the target its distance is the shortest path, in O(m·n) time and space.

## Intuition
A grid is just a graph in disguise: each cell is a node, and each cell has up to 4 (or 8) neighbours. Run BFS exactly as on a graph — the only difference is generating neighbours on the fly via direction vectors, and pruning out-of-bounds or obstacle cells. Marking visited as soon as you enqueue keeps the queue size bounded by O(m·n) and ensures O(m·n) total work.

## Algorithm
1. Define `DIRS = [(-1,0), (1,0), (0,-1), (0,1)]` for 4-connectivity (or include diagonals for 8).
2. Push the start cell into the queue, mark it visited.
3. While the queue is non-empty:
   - Pop `(r, c)`. If it's the target, return its distance.
   - For each `(dr, dc)` in `DIRS`, compute `(nr, nc)`. If it's in bounds, not an obstacle, and not visited, enqueue it and mark visited.

```cpp
const vector<pair<int, int>> DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

int shortestPath(const vector<string>& grid, pair<int, int> start, pair<int, int> target) {
    int m = (int)grid.size(), n = (int)grid[0].size();
    queue<tuple<int, int, int>> q;
    q.push({start.first, start.second, 0});
    vector<vector<bool>> seen(m, vector<bool>(n, false));
    seen[start.first][start.second] = true;
    while (!q.empty()) {
        auto [r, c, d] = q.front();
        q.pop();
        if (make_pair(r, c) == target) return d;
        for (auto [dr, dc] : DIRS) {
            int nr = r + dr, nc = c + dc;
            if (0 <= nr && nr < m && 0 <= nc && nc < n && grid[nr][nc] != '#'
                    && !seen[nr][nc]) {
                seen[nr][nc] = true;
                q.push({nr, nc, d + 1});
            }
        }
    }
    return -1;
}
```

```java
class Solution {
    static final int[][] DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    static int shortestPath(String[] grid, int[] start, int[] target) {
        int m = grid.length, n = grid[0].length();
        Deque<int[]> q = new ArrayDeque<>();
        q.add(new int[] {start[0], start[1], 0});
        boolean[][] seen = new boolean[m][n];
        seen[start[0]][start[1]] = true;
        while (!q.isEmpty()) {
            int[] cur = q.poll();
            int r = cur[0], c = cur[1], d = cur[2];
            if (r == target[0] && c == target[1]) return d;
            for (int[] dir : DIRS) {
                int nr = r + dir[0], nc = c + dir[1];
                if (0 <= nr && nr < m && 0 <= nc && nc < n && grid[nr].charAt(nc) != '#'
                        && !seen[nr][nc]) {
                    seen[nr][nc] = true;
                    q.add(new int[] {nr, nc, d + 1});
                }
            }
        }
        return -1;
    }
}
```

```python
from collections import deque

DIRS = [(-1, 0), (1, 0), (0, -1), (0, 1)]

def shortest_path(grid, start, target):
    m, n = len(grid), len(grid[0])
    q = deque([(*start, 0)])
    seen = {start}
    while q:
        r, c, d = q.popleft()
        if (r, c) == target:
            return d
        for dr, dc in DIRS:
            nr, nc = r + dr, c + dc
            if 0 <= nr < m and 0 <= nc < n and grid[nr][nc] != '#' and (nr, nc) not in seen:
                seen.add((nr, nc))
                q.append((nr, nc, d + 1))
    return -1
```

## Walkthrough
3×3 grid, `.` open, `#` wall, start `(0,0)`, target `(2,2)`:

```
. . .
. # .
. . .
```

1. Enqueue `(0,0,0)`. Pop → `DIRS` order is up, down, left, right, so enqueue `(1,0)` then `(0,1)`, both at dist 1.
2. Pop `(1,0,1)` → enqueue `(2,0)` at dist 2. `(1,1)` is a wall, skip.
3. Pop `(0,1,1)` → enqueue `(0,2)` at dist 2.
4. Pop `(2,0,2)` → enqueue `(2,1)` at dist 3.
5. Pop `(0,2,2)` → enqueue `(1,2)` at dist 3.
6. Pop `(2,1,3)` → enqueue `(2,2)` at dist 4. Pop `(1,2,3)` → `(2,2)` is already seen, skip.
7. Pop `(2,2,4)` — it's the target. Return 4.

## Complexity

- time **O(m · n)**
- space **O(m · n)**

## Pitfalls
- **Bounds-check before indexing** — `0 <= nr < m and 0 <= nc < n`. Python lists with negative indices silently wrap around and corrupt results.
- **Mark visited on enqueue, not dequeue** — otherwise the same cell ends up in the queue multiple times.
- For **8-connectivity**, double-check whether the problem actually allows diagonal moves — many do not.
- **Multi-source BFS** is just BFS with all sources seeded at distance 0 — don't write a loop running BFS once per source (that's O(s · m · n)).
- For **weighted grid moves** (e.g. some cells cost 5, some cost 1), BFS is wrong — use Dijkstra or 0-1 BFS depending on weight values.
