## Problem
Given a stream of search queries with weights, design a structure that returns the top-3 suggestions matching the current prefix, updated as the user types each character.

## Interview-ready explanation
This is a trie where each node also caches its top-K completions. The key insight is that the trie answers which words share this prefix, and a per-node cache answers which of those are best, so a query does not have to search the whole subtree. On insert I walk the word's path and, at every node on it, merge the word into that node's sorted top-K list (highest frequency first, ties broken by lexicographic order). On query I walk the prefix and return the cached list at the node where the walk ends. Queries cost O(L), inserts cost O(L·K) (each of the L nodes merges into a list of size K, plus a small sort if you sort), and the caches take O(total characters × K) space. The alternative is to skip the cache and DFS the subtree at query time: cheaper writes, slower reads.

**One-liner:** Autocomplete walks the prefix in a trie in O(L) and returns a top-K list cached at that node, which every insert updates along its path, trading O(L·K) writes for fast reads.

## Intuition
A trie walks each new character in O(1). The expensive part is "give me the best-K queries below this node." Two strategies: **(a)** at each node cache a sorted list of top-K candidates and update it on insert — fast queries, slower writes; **(b)** at query time DFS below the node collecting candidates into a heap — slower queries, no cache. For LC 1268 the dictionary is static, so option (b) is fine after sorting the words. For LC 642 the stream is hot — option (a) wins. Either way, the trie does the prefix selection; the candidate ranking is a separate per-node concern.

```cpp
struct Node {
    unordered_map<char, Node*> kids;
    vector<pair<int, string>> top;  // top = sorted list of (-freq, word)
};

void insert(Node* root, const string& word, int freq, int K = 3) {
    Node* node = root;
    for (char ch : word) {
        if (!node->kids.count(ch)) node->kids[ch] = new Node();
        node = node->kids[ch];
        node->top.push_back({-freq, word});  // assumes each word is inserted once
        sort(node->top.begin(), node->top.end());  // or use a small heap
        if ((int)node->top.size() > K) node->top.resize(K);
    }
}

vector<string> suggest(Node* root, const string& prefix) {
    Node* node = root;
    for (char ch : prefix) {
        auto it = node->kids.find(ch);
        if (it == node->kids.end()) return {};
        node = it->second;
    }
    vector<string> out;
    for (auto& entry : node->top) out.push_back(entry.second);
    return out;
}
```

```java
class Solution {
    record Entry(int negFreq, String word) {}  // (-freq, word)

    static class Node {
        Map<Character, Node> kids = new HashMap<>();
        List<Entry> top = new ArrayList<>();  // sorted by (-freq, word)
    }

    static void insert(Node root, String word, int freq, int K) {
        Node node = root;
        for (char ch : word.toCharArray()) {
            node = node.kids.computeIfAbsent(ch, k -> new Node());
            node.top.add(new Entry(-freq, word));  // assumes each word is inserted once
            node.top.sort(Comparator.comparingInt(Entry::negFreq).thenComparing(Entry::word));
            if (node.top.size() > K) node.top = new ArrayList<>(node.top.subList(0, K));
        }
    }

    static void insert(Node root, String word, int freq) { insert(root, word, freq, 3); }

    static List<String> suggest(Node root, String prefix) {
        Node node = root;
        for (char ch : prefix.toCharArray()) {
            node = node.kids.get(ch);
            if (node == null) return new ArrayList<>();
        }
        List<String> out = new ArrayList<>();
        for (Entry e : node.top) out.add(e.word());
        return out;
    }
}
```

```python
class Node:
    __slots__ = ("kids", "top")
    def __init__(self):
        self.kids, self.top = {}, []      # top = sorted list of (-freq, word)

def insert(root, word, freq, K=3):
    node = root
    for ch in word:
        node = node.kids.setdefault(ch, Node())
        node.top.append((-freq, word))    # assumes each word is inserted once; to bump a frequency, drop its old entry first
        node.top.sort()                   # or use a small heap
        node.top = node.top[:K]

def suggest(root, prefix):
    node = root
    for ch in prefix:
        node = node.kids.get(ch)
        if not node: return []
    return [w for _, w in node.top]
```

## Walkthrough
Example: insert `("car", 5)`, `("cat", 3)`, `("cab", 2)` with `K = 2`. Then query prefix `"ca"`.

1. **Insert "car" (freq 5).** Build chain `c → a → r`; every node on the path gets `("car":5)` added to its `topK`. After this insert, all three nodes show `topK = [car:5]`.
2. **Insert "cat" (freq 3).** Walk `c → a` (reuse), create `t` under `a`. Push `("cat":3)` into the topK of `c`, `a`, and the new `t` node — each cache is re-sorted by frequency descending, K=2. Nodes `c` and `a` now show `[car:5, cat:3]`; `t` shows `[cat:3]`.
3. **Insert "cab" (freq 2).** Walk `c → a`, create `b`. Push `("cab":2)`. At node `c` and `a` the candidate set becomes `{car:5, cat:3, cab:2}` → sort by freq desc → keep top-2 → `[car:5, cat:3]`. **`cab` is evicted from the cache** (K=2). Node `b` shows `[cab:2]`.
4. **Query "ca" — walk the prefix.** Start at root, walk `c`, then `a`. The walk ends at node `a`; just **read its cached `topK`**.
5. **End.** `topK(a) = [car:5, cat:3]` → suggestions are `["car", "cat"]`.

## Complexity

time **O(L·K) insert / O(L) query** · space **O(Σ L · K)**

## Pitfalls
- Sorting the cached list with the wrong tie-breaker — LC 642 wants higher frequency first, then lexicographically smaller.
- Updating top-K only at the deepest node — every ancestor on the insert path needs the update.
- Recomputing top-K from scratch at each insert instead of merging the new candidate into the existing K.
- For LC 1268 (static dictionary), people overbuild — `bisect` on a sorted list gives O(log n) per character, no trie needed.
- For very long prefixes, the cached list at each ancestor wastes memory — switch to query-time DFS if `Σ L · K` blows up.
