## Problem
Implement `insert(word)`, `search(word)`, `startsWith(prefix)` over a dictionary of lowercase strings.

## Interview-ready explanation
This is a trie, or prefix tree. Each node holds a map from character to child plus an `end` flag that marks where a stored word finishes, so words with a shared prefix share one path from the root. Insert walks the word character by character, creating missing children, and sets `end` on the last node. Search walks the same path and succeeds only if the path exists and the last node has `end` set, while `startsWith` only needs the path to exist. Every operation is O(L) for a string of length L, no matter how many words are stored, and space is O(total characters inserted) nodes.

**One-liner:** A trie stores words as root-to-node paths of characters with an end-of-word flag, so insert, search and startsWith each walk one path in O(L) time, independent of the number of words.

## Intuition
A trie collapses shared prefixes into one branch. Every node owns a child map (a 26-slot array works for lowercase-only input; the code below uses a dict) and an `is_end` flag (called `end` in the code). **Insert** walks the string, creating children on demand. **Search** walks the same path and returns `node.is_end` at the final step. **`startsWith`** is identical to search except it ignores `is_end` — reaching the last character is enough. The win is structural: N words with a shared K-character prefix cost O(K + sum of suffix lengths) total, not O(N·K).

```cpp
class Trie {
    unordered_map<char, Trie*> kids;
    bool end = false;

    Trie* walk(const string& s) {
        Trie* node = this;
        for (char ch : s) {
            auto it = node->kids.find(ch);
            if (it == node->kids.end()) return nullptr;
            node = it->second;
        }
        return node;
    }

public:
    Trie() {}

    void insert(string word) {
        Trie* node = this;
        for (char ch : word) {
            if (!node->kids.count(ch)) node->kids[ch] = new Trie();
            node = node->kids[ch];
        }
        node->end = true;
    }

    bool search(string word) {
        Trie* n = walk(word);
        return n != nullptr && n->end;
    }

    bool startsWith(string prefix) { return walk(prefix) != nullptr; }
};
```

```java
class Trie {
    private final Map<Character, Trie> kids = new HashMap<>();
    private boolean end = false;

    public Trie() {}

    public void insert(String word) {
        Trie node = this;
        for (char ch : word.toCharArray()) {
            node = node.kids.computeIfAbsent(ch, k -> new Trie());
        }
        node.end = true;
    }

    private Trie walk(String s) {
        Trie node = this;
        for (char ch : s.toCharArray()) {
            node = node.kids.get(ch);
            if (node == null) return null;
        }
        return node;
    }

    public boolean search(String word) {
        Trie n = walk(word);
        return n != null && n.end;
    }

    public boolean startsWith(String prefix) { return walk(prefix) != null; }
}
```

```python
class Trie:
    def __init__(self):
        self.kids = {}
        self.end = False

    def insert(self, word):
        node = self
        for ch in word:
            node = node.kids.setdefault(ch, Trie())
        node.end = True

    def _walk(self, s):
        node = self
        for ch in s:
            node = node.kids.get(ch)
            if node is None: return None
        return node

    def search(self, word):       return bool((n := self._walk(word)) and n.end)
    def startsWith(self, prefix): return self._walk(prefix) is not None
```

## Walkthrough
Example below inserts `["car", "cat", "cab"]` into an empty trie.

1. **Insert "car".** From the empty root, create `c → a → r` as a fresh chain and mark `r` as an end node.
2. **Insert "cat".** Walk `c → a` (already exist — reuse them), then create a new `t` child under `a` and mark it end.
3. **Insert "cab".** Walk `c → a` again, create a third sibling `b` under `a`, mark it end. Node `a` now has three end-children: `r`, `t`, `b`.
4. **`search("cat")`.** Walk `c → a → t`; final node has `end == True` → **FOUND**. (Try the companion `trie-search` viz over `{car, cat, cab, dog, do}` — same walk, the terminal check is what changes.)
5. **`search("ca")` vs `startsWith("ca")`.** Both walk to node `a`; `search` returns **False** because `a.end == False`, while `startsWith` returns **True** because reaching the node at all is enough.

The companion `trie-search` visualization shows the same tree being traversed — search/`startsWith` re-use the walk; only the terminal check differs.

## Complexity

time **O(L) per op** · space **O(Σ L)**

## Pitfalls
- Forgetting `is_end` and letting `search("ca")` return True after inserting "cat".
- Using a 26-slot array when input may contain uppercase/digits — switch to a hashmap.
- Storing the full word at every node (wastes memory); store it only at end nodes if you need to retrieve it.
- Iterative is cleaner than recursive for insert/search — saves stack frames on long strings.
- For deletion, you need a count of descendants or a `children_count` field; naive "unmark end" leaks nodes.
