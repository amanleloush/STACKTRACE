## Problem
Given a sorted array `arr` and a target value, return the index of the target or `-1` if it's not present.

## Interview-ready explanation

This is classic binary search on a sorted array. I keep an inclusive range lo to hi, with the invariant that if the target exists, it is inside that range. Each step I check the middle element: if it equals the target I return its index; if it is smaller, the target can only be to the right, so lo becomes mid + 1; otherwise hi becomes mid - 1. When lo passes hi the range is empty and I return -1. The range halves every step, so it is O(log n) time and O(1) space.

**One-liner:** Compare with the middle of a sorted range and discard the half that can't hold the target, until found or empty; O(log n) time, O(1) space.

## Intuition
Because the array is sorted, comparing the target to the middle element tells you which half can be safely discarded. Each step halves the search range, so after at most `⌊log₂ n⌋ + 1` probes you've either found the target or proven it isn't there. The invariant is simple: if `target` exists, it lives in `[lo, hi]`.

## Algorithm
1. Initialize `lo = 0`, `hi = n - 1`.
2. While `lo <= hi`:
   - Compute `mid = lo + (hi - lo) // 2`.
   - If `arr[mid] == target`, return `mid`.
   - If `arr[mid] < target`, move `lo = mid + 1`.
   - Else move `hi = mid - 1`.
3. If the loop exits, return `-1`.

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int lo = 0, hi = (int)nums.size() - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;  // overflow-safe
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
};
```

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

## Walkthrough
On `arr = [-1, 0, 3, 5, 9, 12]`, `target = 9`:

1. `lo=0, hi=5` → `mid=2`, `arr[2]=3 < 9` → discard left half, `lo=3`.
2. `lo=3, hi=5` → `mid=4`, `arr[4]=9 == 9` → return `4`.

Two probes against six elements — well within the `⌊log₂ 6⌋ + 1 = 3` worst case.

## Pitfalls
- In Java or C++, `(lo + hi) / 2` can overflow a 32-bit int — use `lo + (hi - lo) / 2`. Python ints don't overflow, so `(lo + hi) // 2` is safe there; the code above uses the overflow-safe form out of habit.
- Mixing up `lo <= hi` with `hi = mid` causes infinite loops. Stick to one template.
- Forgetting to return `-1` when the loop exits — easy to fall off the function.
- Assuming the array is sorted when the problem only says "given an array". Re-read the constraints.
- Off-by-one on `hi`: it should be `n - 1` for an inclusive upper bound, not `n`.
