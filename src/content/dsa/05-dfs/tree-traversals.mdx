## Problem
Visit every node of a binary tree exactly once, in one of three canonical orders.

## Interview-ready explanation
All three are the same recursive DFS. The only difference is when I record the node relative to its two subtrees. Pre-order is node, left, right, which is good for copying or serializing a tree. In-order is left, node, right, which gives sorted output on a binary search tree. Post-order is left, right, node, used when a node needs its children's answers first, like height or deleting a tree. Each node is visited once, so it's O(n) time and O(h) space for the recursion stack, where h is the height (O(n) for a skewed tree).

**One-liner:** One recursive DFS where only the position of the visit changes (before, between or after the children): O(n) time, O(h) space.

## Intuition
The three orders differ only in **when you "visit" the node** relative to its children. **Preorder** visits *before* recursing — you see a node before its subtree, perfect for serialization. **Inorder** visits *between* left and right — on a BST it yields sorted output. **Postorder** visits *after* both children return — perfect for any "combine the answers from below" computation (heights, sums, diameters).

## Algorithm
Three nearly identical functions; the only thing that moves is the `visit(node)` line.

```cpp
class Solution {
public:
    vector<int> preorderTraversal(TreeNode* root) {
        vector<int> out;
        preorder(root, out);
        return out;
    }

    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> out;
        inorder(root, out);
        return out;
    }

    vector<int> postorderTraversal(TreeNode* root) {
        vector<int> out;
        postorder(root, out);
        return out;
    }

private:
    void preorder(TreeNode* node, vector<int>& out) {
        if (!node) return;
        out.push_back(node->val);    // visit
        preorder(node->left, out);
        preorder(node->right, out);
    }

    void inorder(TreeNode* node, vector<int>& out) {
        if (!node) return;
        inorder(node->left, out);
        out.push_back(node->val);    // visit
        inorder(node->right, out);
    }

    void postorder(TreeNode* node, vector<int>& out) {
        if (!node) return;
        postorder(node->left, out);
        postorder(node->right, out);
        out.push_back(node->val);    // visit
    }
};
```

```cpp driver
const int NUL = INT_MIN;  // a missing child in LeetCode's level-order input

TreeNode* build(const vector<int>& v) {
    if (v.empty() || v[0] == NUL) return nullptr;
    TreeNode* root = new TreeNode(v[0]);
    queue<TreeNode*> q;
    q.push(root);
    size_t i = 1;
    while (!q.empty() && i < v.size()) {
        TreeNode* node = q.front();
        q.pop();
        if (i < v.size() && v[i] != NUL) q.push(node->left = new TreeNode(v[i]));
        ++i;
        if (i < v.size() && v[i] != NUL) q.push(node->right = new TreeNode(v[i]));
        ++i;
    }
    return root;
}

string show(const vector<int>& v) {
    string s = "[";
    for (size_t i = 0; i < v.size(); ++i)
        s += (i ? ", " : "") + (v[i] == NUL ? string("null") : to_string(v[i]));
    return s + "]";
}
```

```python driver
from collections import deque


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


# @solution


def build(vals):
    if not vals or vals[0] is None:
        return None
    root = TreeNode(vals[0])
    q = deque([root])
    i = 1
    while q and i < len(vals):
        node = q.popleft()
        if i < len(vals) and vals[i] is not None:
            node.left = TreeNode(vals[i])
            q.append(node.left)
        i += 1
        if i < len(vals) and vals[i] is not None:
            node.right = TreeNode(vals[i])
            q.append(node.right)
        i += 1
    return root


def show(vals):
    return "[" + ", ".join("null" if x is None else str(x) for x in vals) + "]"

    [1, 2, 3, 4, 5, 6, 7],  # the walkthrough below

]
```

## Walkthrough
The viz uses a 7-node tree (root `1`, children `2, 3`, grandchildren `4, 5, 6, 7`) and an `order` input that toggles `pre` / `in` / `post`. Default is **inorder**:

1. **Start at root `1`.** Inorder rule: descend left first. Push frames `1 → 2 → 4` until `4` is a leaf.
2. **Visit `4`**, then return to `2` and **visit `2`** (between L and R). Descend right into `5`, **visit `5`**, return.
3. Pop back to `1` and **visit `1`**. Descend right into `3`.
4. From `3`, descend left into `6`, **visit `6`**, return, **visit `3`**, descend right, **visit `7`**.
5. **End.** Inorder output: `4 → 2 → 5 → 1 → 6 → 3 → 7`. Switch the input to `pre` to get `1, 2, 4, 5, 3, 6, 7` or `post` to get `4, 5, 2, 6, 7, 3, 1`.

## Complexity

- time **O(n)**
- space **O(h)** stack, h = tree height

## Pitfalls
- Confusing preorder with BFS — preorder is depth-first, BFS is level-by-level.
- Assuming inorder gives sorted output on any tree — only on a **BST**.
- Hitting recursion limits on a skewed tree of 10⁵ nodes — Python's default recursion limit is 1000.
- Mutating the output list in place when the recursion expects a fresh list per call.
- Writing an iterative version with one stack but forgetting that postorder needs extra bookkeeping: a "visited" flag, a last-visited pointer, or two stacks.
