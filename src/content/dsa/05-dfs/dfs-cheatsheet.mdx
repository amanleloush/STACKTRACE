## Interview-ready explanation
Depth-first search (DFS) explores a graph or tree by following one branch as deep as it goes, then backtracking to the most recent node that still has unexplored neighbours. I implement it with recursion (the call stack) or an explicit stack, and on graphs I keep a visited set so each node is processed once. I can do work before visiting the children (pre-order) or after they return (post-order), which is what makes DFS fit components, flood fill, tree problems and cycle detection. Each node and edge is handled once, so it's O(V + E) time (O(n) on a tree) and O(V) space for the visited set and the stack.

**One-liner:** DFS goes as deep as possible along one path, then backtracks, using recursion or a stack plus a visited set: O(V + E) time, O(V) space.

## Trigger
**You see in the problem:** "connected components", "number of islands", "reachability", "tree traversal (pre/in/post-order)", "cycle detection", "path that satisfies condition X".

**Reach for this pattern when:**
- You need to visit **every node** of a graph/tree, ordering doesn't matter (or post-order does).
- Counting **connected components** / flood fill.
- Detecting **cycles** in directed/undirected graphs (color/state-set DFS).
- The problem has a **recursive natural structure** — trees, nested structures, regions.

**Don't reach for it when:**
- You need *shortest* path in unweighted graph → BFS.
- The graph is huge and you'll blow the recursion stack — switch to iterative DFS or BFS.
- You need to enumerate every path or combination — use backtracking (DFS over a tree of choices that undoes each choice on the way back).

## The mental model
Go deep along one branch until you can't, then backtrack. Either recursion (implicit stack) or an explicit `stack`. Mark visited so you don't loop. For trees, the call structure mirrors the tree; for graphs, you also need `visited`. Three colors (`WHITE/GRAY/BLACK`) detect cycles in directed graphs.

// Recursive DFS on a graph
void dfs(int node, vector<vector<int>>& graph, unordered_set<int>& seen) {
    if (seen.count(node)) return;
    seen.insert(node);
    for (int nxt : graph[node]) dfs(nxt, graph, seen);
}

// Iterative DFS (when stack depth is a worry)
unordered_set<int> dfsIter(int start, vector<vector<int>>& graph) {
    vector<int> stk = {start};
    unordered_set<int> seen;
    while (!stk.empty()) {
        int node = stk.back();
        stk.pop_back();
        if (seen.count(node)) continue;
        seen.insert(node);
        for (int nxt : graph[node])
            if (!seen.count(nxt)) stk.push_back(nxt);
    }
    return seen;
}

// Tree traversals (recursive)
void inorder(TreeNode* node, vector<int>& out) {
    if (!node) return;
    inorder(node->left, out);
    out.push_back(node->val);
    inorder(node->right, out);
}

// Cycle detection in directed graph (3-color)
const int WHITE = 0, GRAY = 1, BLACK = 2;
bool hasCycle(int node, vector<vector<int>>& graph, vector<int>& color) {
    color[node] = GRAY;
    for (int nxt : graph[node]) {
        if (color[nxt] == GRAY) return true;
        if (color[nxt] == WHITE && hasCycle(nxt, graph, color)) return true;
    }
    color[node] = BLACK;
    return false;
}

class Solution {
    // Recursive DFS on a graph
    static void dfs(int node, int[][] graph, Set<Integer> seen) {
        if (seen.contains(node)) return;
        seen.add(node);
        for (int nxt : graph[node]) dfs(nxt, graph, seen);
    }

    // Iterative DFS (when stack depth is a worry)
    static Set<Integer> dfsIter(int start, int[][] graph) {
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(start);
        Set<Integer> seen = new HashSet<>();
        while (!stack.isEmpty()) {
            int node = stack.pop();
            if (seen.contains(node)) continue;
            seen.add(node);
            for (int nxt : graph[node])
                if (!seen.contains(nxt)) stack.push(nxt);
        }
        return seen;
    }

    // Tree traversals (recursive)
    static void inorder(TreeNode node, List<Integer> out) {
        if (node == null) return;
        inorder(node.left, out);
        out.add(node.val);
        inorder(node.right, out);
    }

    // Cycle detection in directed graph (3-color)
    static final int WHITE = 0, GRAY = 1, BLACK = 2;

    static boolean hasCycle(int node, int[][] graph, int[] color) {
        color[node] = GRAY;
        for (int nxt : graph[node]) {
            if (color[nxt] == GRAY) return true;
            if (color[nxt] == WHITE && hasCycle(nxt, graph, color)) return true;
        }
        color[node] = BLACK;
        return false;
    }
}

# Recursive DFS on a graph
def dfs(node, graph, seen):
    if node in seen: return
    seen.add(node)
    for nxt in graph[node]:
        dfs(nxt, graph, seen)

# Iterative DFS (when stack depth is a worry)
def dfs_iter(start, graph):
    stack, seen = [start], set()
    while stack:
        node = stack.pop()
        if node in seen: continue
        seen.add(node)
        for nxt in graph[node]:
            if nxt not in seen: stack.append(nxt)
    return seen

# Tree traversals (recursive)
def inorder(node, out):
    if not node: return
    inorder(node.left, out)
    out.append(node.val)
    inorder(node.right, out)

# Cycle detection in directed graph (3-color)
WHITE, GRAY, BLACK = 0, 1, 2
def has_cycle(node, graph, color):
    color[node] = GRAY
    for nxt in graph[node]:
        if color[nxt] == GRAY: return True
        if color[nxt] == WHITE and has_cycle(nxt, graph, color): return True
    color[node] = BLACK
    return False

## Complexity
- Time: **O(V + E)** for graphs; **O(n)** for trees.
- Space: **O(V)** for visited + recursion stack (worst case O(V) on a path). The iterative skeleton above pushes a node once per incoming edge, so its stack can hold up to O(E) entries.

## Variants in this pattern
1. **Graph traversal** — visit all nodes, count components.
2. **Grid flood fill** — connected regions, islands, color regions.
3. **Tree traversals** — pre / in / post-order; iterative versions with explicit stack.
4. **Path sum / path tracking** — DFS that carries running state (sum, path list).
5. **Cycle detection** — 3-color for directed; parent-check for undirected.
6. **Iterative DFS for deep graphs** — when recursion limit is a problem.

## Common bugs / pitfalls
- **Forgetting `visited`** → infinite recursion on cyclic graphs.
- **Marking visited at wrong time** — for grid flood fill, mark a cell as soon as you *enter* it, before recursing into neighbours. If you mark it only after the recursive calls return, a neighbour can recurse straight back into it (infinite recursion).
- **Recursion limit**: Python's default limit is 1000. Raising it with `sys.setrecursionlimit(10**6)` can still crash the interpreter on very deep inputs, so iterative DFS is the safer choice for big graphs.
- **Undirected cycle detection** can't use 3-color alone — you must skip the parent edge.
- **Mutating the input grid as visited** is clever (no separate visited set) but make sure to restore if the caller cares.
- **Pre/in/post-order confusion**: in-order on a BST gives sorted output; pre-order serializes; post-order = "children first" (deletion, eval).

## In 30 seconds
Go deep, mark visited, backtrack. If shortest path doesn't matter and the structure is recursive — DFS. For directed cycles, paint nodes WHITE/GRAY/BLACK.
