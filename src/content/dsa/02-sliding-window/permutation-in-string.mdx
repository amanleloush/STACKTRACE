## Problem
Given strings `s1` and `s2`, return `true` if **some permutation of `s1`** appears as a contiguous substring of `s2`. Equivalently: does any window of length `|s1|` in `s2` have the same character frequencies as `s1`?

## Interview-ready explanation

A permutation of s1 is any string with the same character counts, so this is a fixed-size sliding window of length k = len(s1) over s2. I keep count arrays for s1 and for the current window, plus a matches counter: how many of the 26 letters currently have equal counts in both. When I slide, one character enters and one leaves, and I update matches only for those two letters, depending on whether each count just became equal or just stopped being equal. If matches reaches 26, the window is a permutation and I return true. Each slide is O(1), so it is O(n + 26) time and O(26) space.

**One-liner:** Slide a window of length len(s1) over s2 and keep a count of letters whose frequencies match, so each slide is O(1); O(n) time.

## Intuition
A permutation is fully characterized by its character-frequency map. Slide a fixed-size window of length `k = |s1|` across `s2`. Maintain a rolling frequency map for the window; compare against `need = Counter(s1)`. Naively comparing two maps every step is O(σ) per step — replace it with a **match counter** `matches` that increments when a character's window-count *equals* `need[ch]`, decrements when it stops matching. The window is a permutation if and only if `matches == 26` (over the lowercase-English alphabet). Each slide does O(1) work, and the initial setup costs O(k + σ), so the total is O(n + σ), where σ is the alphabet size.

## Algorithm
1. If `|s1| > |s2|`, return `false`.
2. Build `need` and `have` as size-26 arrays (`have` over the first window `s2[0..k-1]`). Initialize `matches`: number of letters where `have[i] == need[i]`. If `matches == 26`, return `true`.
3. For `r` in `k..n-1`:
   - Add `s2[r]` to `have`; update `matches`.
   - Remove `s2[r - k]` from `have`; update `matches`.
   - If `matches == 26`, return `true`.
4. (The initial window is checked once before the loop starts.) If no window matched, return `false`.

```cpp
class Solution {
public:
    bool checkInclusion(string s1, string s2) {
        int k = (int)s1.size(), n = (int)s2.size();
        if (k > n) return false;
        vector<int> need(26, 0), have(26, 0);
        for (char ch : s1) need[ch - 'a'] += 1;
        for (int i = 0; i < k; ++i) have[s2[i] - 'a'] += 1;
        int matches = 0;
        for (int i = 0; i < 26; ++i) if (need[i] == have[i]) matches += 1;
        if (matches == 26) return true;
        for (int r = k; r < n; ++r) {
            int ai = s2[r] - 'a';
            have[ai] += 1;
            if (have[ai] == need[ai]) matches += 1;
            else if (have[ai] == need[ai] + 1) matches -= 1;
            int bi = s2[r - k] - 'a';
            have[bi] -= 1;
            if (have[bi] == need[bi]) matches += 1;
            else if (have[bi] == need[bi] - 1) matches -= 1;
            if (matches == 26) return true;
        }
        return false;
    }
};
```

```java
        int k = s1.length(), n = s2.length();
        if (k > n) return false;
        int[] need = new int[26], have = new int[26];

            else if (have[bi] == need[bi] - 1) matches -= 1;
            if (matches == 26) return true;
```

```python
def check_inclusion(s1, s2):
    k, n = len(s1), len(s2)
    if k > n: return False
    need, have = [0]*26, [0]*26
    for ch in s1: need[ord(ch) - 97] += 1
    for i in range(k): have[ord(s2[i]) - 97] += 1
    matches = sum(1 for i in range(26) if need[i] == have[i])
    if matches == 26: return True
    for r in range(k, n):
        ai = ord(s2[r]) - 97
        have[ai] += 1
        if have[ai] == need[ai]: matches += 1
        elif have[ai] == need[ai] + 1: matches -= 1
        bi = ord(s2[r - k]) - 97
        have[bi] -= 1
        if have[bi] == need[bi]: matches += 1
        elif have[bi] == need[bi] - 1: matches -= 1
        if matches == 26: return True
    return False
```

## Walkthrough
On `s1 = "ab"`, `s2 = "eidbaooo"`, `k = 2`, `need = {a:1, b:1}`:

1. **Initial window** covers `s2[0..1] = "ei"`. `window = {e:1, i:1}` — nowhere near `need`.
2. Slide: `+'d', -'e'` → `"id"`, window = `{i:1, d:1}`. Still off.
3. Slide: `+'b', -'i'` → `"db"`, window = `{d:1, b:1}`. Closer — `b` matches.
4. Slide: `+'a', -'d'` → `"ba"`, window = `{b:1, a:1}` — **exactly equal to `need`**. Return `true`.

## Complexity

- time **O(n + σ)**
- space **O(σ)** alphabet size

## Pitfalls
- Comparing full frequency maps every step — works, but O(n·σ); use the `matches` trick to keep it O(n).
- Off-by-one when initializing the first window — it's `s2[0..k-1]`, not `s2[0..k]`.
- Updating `matches` on the wrong side — increment when count *just hit* the requirement; decrement when it *just left*. Use exact equality checks; `>=` is wrong.
- For "find all anagrams" (LC 438), the engine is identical — just emit `l` whenever `matches == 26` instead of returning.
- Unicode strings — replace the `[26]` array with a hash map.
