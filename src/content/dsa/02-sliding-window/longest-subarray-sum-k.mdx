## Problem
Given an array of **non-negative** integers and an integer `K`, return the length of the longest contiguous subarray whose sum is at most `K`.

## Interview-ready explanation

This is a variable-size sliding window, and it works only because the numbers are non-negative: growing the window can only raise the sum, and shrinking it can only lower it. I move r forward, adding arr[r] to a running sum. While the sum is greater than K, I subtract arr[l] and move l forward. After that the window is the longest valid one ending at r, so I update the best length with r - l + 1. Each index enters and leaves the window at most once, so it is O(n) time and O(1) space. With negative numbers this breaks, and I would switch to prefix sums.

**One-liner:** Because all values are non-negative, expand right and shrink left while the sum exceeds K, recording the longest valid window; O(n) time, O(1) space.

## Intuition
Non-negativity makes the window *monotone*: adding an element can only increase the sum, so if `[l, r]` violates `sum <= K`, every wider window does too — `l` must advance. That's the magic that makes the sliding window correct. Maintain a running `s`; expand `r`, and whenever `s > K`, shrink `l` until `s <= K` again. The invariant: at every step, `s == sum(arr[l..r])` and the window is the *longest valid window ending at `r`*. Each index moves at most twice, so the sweep is O(n). Without the non-negativity assumption, you'd need prefix sums plus a sorted structure or binary search instead. The `l <= r` guard only matters when `K` is negative: then even an empty window has sum `0 > K`, and without the guard `l` would run off the end of the array.

## Algorithm
1. `l = 0, s = 0, best = 0`.
2. For `r` in 0..n-1:
   - `s += arr[r]`.
   - While `s > K` (and the window is non-empty, `l <= r`): `s -= arr[l]; l += 1`.
   - `best = max(best, r - l + 1)`.
3. Return `best`.

```cpp
int longestSumAtMostK(const vector<int>& arr, int K) {
    int l = 0, s = 0, best = 0;
    for (int r = 0; r < (int)arr.size(); ++r) {
        s += arr[r];
        while (s > K && l <= r) {
            s -= arr[l];
            l += 1;
        }
        best = max(best, r - l + 1);
    }
    return best;
}
```

## Walkthrough
On `arr = [2, 1, 5, 1, 3, 2]`, `K = 7`:

1. **Extend.** `r=0` → `sum=2`, window `[2]`, `best=1`. `r=1` → `sum=3`, window `[2,1]`, `best=2`.
2. `r=2` → `sum=8 > 7`. **Shrink:** drop `arr[0]=2`, `sum=6`, `l=1`. Window `[1,5]`, `best` stays at `2`.
3. `r=3` → `sum=7`, exactly at the limit. Window `[1,5,1]`, `best=3`.
4. `r=4` → `sum=10 > 7`. Shrink: drop `1` → `9`, drop `5` → `4`, now `l=3`. Window `[1,3]`. `r=5` → `sum=6`, window `[1,3,2]`, length 3, `best` stays at `3`.
5. **End.** Return `best = 3`.

## Complexity

- time **O(n)**
- space **O(1)**

## Pitfalls
- **Negative numbers break the monotonicity.** With negatives, shrinking left can make the sum *grow*, so the window can't shrink-only. Switch to prefix sums + sorted structure.
- Confusing `<= K` with `== K`. For exact-K problems, use a hash map of prefix sums.
- Forgetting to update `best` *after* the inner while — the window must be valid first.
- "Minimum size subarray sum ≥ K" (LC 209) is the mirror — shrink while `s >= K`, record on shrink.
