## Problem
Given an array and an integer `k`, return the **maximum sum** of any contiguous subarray of length exactly `k` (assume `1 ≤ k ≤ n`).

## Interview-ready explanation

This is a fixed-size sliding window. Two neighbouring windows of length k share k - 1 elements, so I don't recompute each sum from scratch. I sum the first k elements once, then slide one step at a time: add the element entering on the right, arr[r], and subtract the element leaving on the left, arr[r - k], updating the best sum as I go. Each slide is O(1), so the total is O(n) time and O(1) space, instead of O(n·k) for summing every window separately.

**One-liner:** Sum the first k elements, then slide by adding the new right element and subtracting the one that left, tracking the max; O(n) time, O(1) space.

## Intuition
Two consecutive windows differ by one element on each end. Compute the sum of the first window in O(k), then for each subsequent step *roll* the sum: add the new right element, subtract the leftmost. Each transition is O(1), so the whole pass is O(n). The invariant is `windowSum == sum(arr[l..r])` at every step — never recompute, just adjust.

## Algorithm
1. Compute `s = sum(arr[0..k-1])`. Set `best = s`.
2. For `r = k .. n-1`:
   - `s += arr[r] - arr[r - k]` (add new, drop old).
   - `best = max(best, s)`.
3. Return `best`.

```cpp
int maxSumK(const vector<int>& arr, int k) {
    int s = 0;
    for (int i = 0; i < k; ++i) s += arr[i];
    int best = s;
    for (int r = k; r < (int)arr.size(); ++r) {
        s += arr[r] - arr[r - k];  // add new, drop old
        best = max(best, s);
    }
    return best;
}
```

```java
class Solution {
    static int maxSumK(int[] arr, int k) {
        int s = 0;
        for (int i = 0; i < k; i++) s += arr[i];
        int best = s;
        for (int r = k; r < arr.length; r++) {
            s += arr[r] - arr[r - k];  // add new, drop old
            best = Math.max(best, s);
        }
        return best;
    }
}
```

## Walkthrough
On `arr = [2, 1, 5, 1, 3, 2]`, `k = 3`:

- Step 1 — initial window `[2, 1, 5]`: `s = 8`, `best = 8`.
- Step 2 — `r=3`: add `arr[3]=1`, drop `arr[0]=2`. `s = 7`. `best` stays at 8.
- Step 3 — `r=4`: add `arr[4]=3`, drop `arr[1]=1`. `s = 9`. `best = 9`.
- Step 4 — `r=5`: add `arr[5]=2`, drop `arr[2]=5`. `s = 6`. `best` stays at 9.

Return `9` (window `[5, 1, 3]`).

## Complexity

- time **O(n)**
- space **O(1)**

## Pitfalls
- Off-by-one on the initial window — make sure the first sum covers exactly `arr[0..k-1]`.
- Subtracting `arr[r - k + 1]` instead of `arr[r - k]` — the element leaving is the one at the *old* left index.
- Recomputing the sum each step — that's O(n·k); the whole point of rolling is to drop that factor.
- For "max of window" (not sum), use a **monotonic deque** — running max needs more than addition/subtraction.
